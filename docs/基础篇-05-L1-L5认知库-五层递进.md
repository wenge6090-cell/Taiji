# 基础篇·05：L1-L5 认知库——五层递进的认知架构

> **核心论点**：主流 Agent 框架的"记忆"只有一层——把历史对话塞进上下文。太极架构将认知资产划分为五个独立层级：技能（L1）、模型（L2）、格栅（L3）、真理（L4）、自我意识（L5）。这不是分层存储，而是**递进抽象**——每层从前一层提炼、浓缩、升华。L1 存"怎么做"，L2 存"什么模式"，L3 存"什么时候用什么模式"，L4 存"为什么这样用"，L5 存"我是谁"。

---

## 引言：为什么你的 Agent 永远记不住该记住的？

试试问一个 Agent 这个问题：

> "你第 15 轮犯了一个错误——把分析报告写进了 README 而不是 docs 目录。第 20 轮你又犯了同样的错误。为什么？"

答案是：**它根本不记得自己犯过错误。**

不是因为它没有上下文——上下文里有。而是因为**上下文中的"错误记录"和"成功记录"混在一起**，没有结构化区分。Agent 的注意力被稀释了，它分不清哪些信息是"工具定义"，哪些是"历史日志"，哪些是"经验教训"。

在主流框架中，所有的"记忆"就是**一个桶**：

```
Agent Memory = [System Prompt] + [Full History Logs] + [Tool Definitions]
```

这个桶的问题是：
1. **没有层级** — 工具定义和历史日志混在一起
2. **没有抽象** — 具体事件和经验模式混在一起
3. **没有优先级** — 关键教训和无关细节权重相同
4. **没有演化** — 记忆只增不减，不会提炼升级

太极架构的解法是：**L1-L5 五层认知库**——每一层都是对下一层的提炼和抽象。

## 第一章：五层认知库总览

### 1.1 从数据到智慧的五层漏斗

```
        原始执行数据（不存入认知库，活在上下文中）
                    │
                    ▼
  ┌─────────────────────────────────────┐
  │  L1: 技能层（工具定义 + 操作方式）    │ ← 最具体，最频繁使用
  │      "如何调用 read_file"            │
  ├─────────────────────────────────────┤
  │  L2: 模型层（经验模式 + 工作流模板）  │
  │      "搜索时先用英文关键词更有效"      │
  ├─────────────────────────────────────┤
  │  L3: 格栅层（八卦认知网格 + 情境映射） │
  │      "探索期用震卦，产出期用兑卦"      │
  ├─────────────────────────────────────┤
  │  L4: 真理层（底层原则 + 认知约束）    │
  │      "禁止连续两轮纯读"               │
  ├─────────────────────────────────────┤
  │  L5: 自我意识层（身份认知 + 元认知）   │
  │      "我是太极架构的学习型 Agent"      │ ← 最抽象，最稳定
  └─────────────────────────────────────┘
```

每一层的核心特征：

| 层级 | 名称 | 抽象程度 | 更新频率 | 存储形式 | 访问频率 |
|------|------|---------|---------|---------|---------|
| L1 | 技能层 | 低（具体操作） | 低（工具稳定时不变） | JSON/函数定义 | 每轮必用 |
| L2 | 模型层 | 中（经验模式） | 中（每几轮更新） | JSON/自然语言 | 每轮必查 |
| L3 | 格栅层 | 高（情境映射） | 低（架构级稳定） | JSON/八卦映射表 | 每轮必用 |
| L4 | 真理层 | 极高（底层原则） | 极低（几乎不变） | 自然语言规则 | 触发时查 |
| L5 | 自我意识层 | 最高（身份认知） | 几乎不变 | 自然语言描述 | 每轮必用 |

### 1.2 与传统框架"记忆层"的对比

| 维度 | 主流框架 | 太极 L1-L5 |
|------|---------|------------|
| 层级数量 | 1层（上下文拼接） | 5层（递进抽象） |
| 层级间关系 | 无（平铺堆叠） | 递进（下层支撑上层） |
| 信息密度 | 低（原始日志） | 高（提炼模式） |
| 检索效率 | O(n) 线性扫描 | O(1) 层级定位 |
| 跨会话持久性 | 无 | 有（认知库持久化） |
| 演化能力 | 无（只增不减） | 有（下层经验→上层模式） |

## 第二章：L1 技能层——"怎么做"

### 2.1 定义

L1 技能层是认知库中**最具体、最操作化**的一层。它定义 Agent 可以调用的所有工具及其使用方式。

### 2.2 存储内容

```
L1 技能库示例：
{
  "read_file": {
    "description": "读取文件内容",
    "parameters": ["path", "start_line (optional)", "end_line (optional)"],
    "usage_example": "read_file(path='/data/report.md', start_line=1, end_line=50)",
    "success_patterns": [
      "路径必须是绝对路径或相对当前工作目录",
      "大文件分片读取比一次性读取更稳定"
    ],
    "failure_patterns": [
      "不存在的路径会返回错误，应先 list_directory 确认",
      "二进制文件用 exec('file path') 检测类型后再读取"
    ]
  },
  "write_file": {
    "description": "写入内容到文件",
    "parameters": ["path", "content"],
    "usage_example": "write_file(path='/output/summary.md', content='# 总结...')",
    "success_patterns": [
      "先确保目标目录存在，不存在则用 exec('mkdir -p') 创建",
      "覆盖写入前先 read_file 确认当前内容"
    ],
    "failure_patterns": [
      "写入不存在的目录会失败",
      "内容过长时应分批写入"
    ]
  },
  "web_search": {
    "description": "搜索网络信息",
    "parameters": ["query", "source (optional)"],
    "success_patterns": [
      "使用 site: 语法限定域名可提高准确度",
      "中英文混合关键词效果优于纯中文"
    ],
    "failure_patterns": [
      "过于宽泛的查询返回大量无关结果",
      "需要多轮迭代搜索才有深度"
    ]
  }
}
```

### 2.3 L1 的演化方式

L1 技能层通过 DMN 的**失败分析**来演化：

```
TPN 执行失败：read_file 读取了一个目录路径
    │
    ▼
暗驱捕获错误："read_file 不能读取目录，需要先用 list_directory"
    │
    ▼
DMN 更新 L1：
在 read_file.failure_patterns 中添加：
"路径是目录时会失败，执行前应先用 list_directory 确认路径类型"
```

这种演化是**增量式**的——工具本身不改变，但对工具的使用约束在持续精细化。

### 2.4 Weaver 如何使用 L1

Weaver 在"织"环节从 L1 技能库中**选择性加载**当前轮次需要的工具定义：

```python
# Weaver 的 L1 加载逻辑
class Weaver:
    def _load_l1_skills(self, perception, posture):
        """加载当前轮次需要的技能"""
        # 基础技能（所有轮次都需要）
        base_skills = ["read_file", "write_file", "list_directory"]
        
        # 根据认知姿态添加技能
        if posture == "震卦" or posture == "巽卦":
            # 探索/分析期需要搜索能力
            base_skills.append("web_search")
            base_skills.append("web_fetch")
        elif posture == "兑卦":
            # 输出期不需要搜索
            pass
        
        # 从 L1 库加载完整定义
        return {name: l1_skills[name] for name in base_skills}
```

关键设计：**不是所有工具都在系统提示词中**。只加载当前轮次需要的工具，减少注意力分散。

## 第三章：L2 模型层——"什么模式有效"

### 3.1 定义

L2 模型层存储的是**从执行经验中提炼的可复用模式**。如果说 L1 是"怎么做"，L2 就是"什么方式更有效"。

### 3.2 存储内容

L2 模型不是代码，而是**结构化的经验描述**：

```json
{
  "search_strategy": {
    "type": "pattern",
    "domain": "信息检索",
    "trigger_condition": "轮次 >= 3 且任务类型为信息收集",
    "pattern": "宽泛搜索在前 2 轮有效，第 3 轮后应转向精准搜索",
    "confidence": 0.85,
    "evidence_count": 12,
    "source_rounds": [1, 2, 3, 5, 7, 10],
    "counter_examples": ["当目标是市场全景时，宽泛搜索可持续到第 5 轮"]
  },
  "writing_flow": {
    "type": "workflow",
    "domain": "内容创作",
    "steps": [
      "先收集至少 3 个可信来源",
      "再构建大纲（标题+子标题）",
      "逐段填充，每段不超过 300 字",
      "全文写完后通读检查逻辑连贯性"
    ],
    "confidence": 0.92,
    "evidence_count": 8
  },
  "debugging_pattern": {
    "type": "pattern",
    "domain": "故障排查",
    "trigger_condition": "工具调用返回错误",
    "pattern": "先检查参数类型，再检查路径是否存在，最后检查权限",
    "confidence": 0.78,
    "evidence_count": 5
  }
}
```

### 3.3 L2 的演化方式

L2 模型的演化是**DMN 的核心产出**：

```
TPN 执行多轮后积累日志
    │
    ▼
暗驱分析日志，发现重复模式：
"第 1、2、3 轮搜索使用中文关键词，结果不理想"
"第 4 轮改用英文关键词 + site:gov，结果大幅提升"
"第 5、6 轮延续英文关键词策略，效果稳定"
    │
    ▼
DMN 提取模式：
{
  "pattern": "英文关键词 + 站点限定",
  "trigger_condition": "搜索国际经济数据",
  "confidence": 0.85
}
    │
    ▼
存入 L2 模型库（confidence > 0.7 生效）
```

**置信度机制**：
- 新模式 confidence 从 0.5 开始
- 每次成功复用 +0.1，失败 -0.15
- confidence > 0.7 才会被 Weaver 加载
- confidence < 0.3 自动淘汰

### 3.4 Weaver 如何使用 L2

Weaver 加载 L2 模型时，会根据当前轮次的**任务类型**和**情境特征**进行匹配：

```python
class Weaver:
    def _load_l2_models(self, perception):
        """加载与当前情境匹配的经验模式"""
        task_type = perception.task_type  # 搜索/写作/分析/编码
        round_num = perception.round_num
        recent_failures = perception.recent_failures
        
        matched = []
        for model in l2_models.all():
            # 检查触发条件
            if model.matches(task_type, round_num, recent_failures):
                if model.confidence >= 0.7:
                    matched.append(model)
        
        # 按置信度排序，取 top 5
        matched.sort(key=lambda m: -m.confidence)
        return matched[:5]
```

如果说 L2 是"已知的模式"，L3 就是"选择模式的模式"——**元策略层**。

### 4.3 L3 的演化方式

L3 格栅的更新比 L1 和 L2 **更谨慎**。它的演化通常发生在以下情况：

1. **发现新的有效姿态组合**：当 L2 模型频繁匹配到某个姿态时，L3 格栅的触发条件会被细化
2. **架构级反思**：当 DMN 发现某些姿态长期未被使用，会检查是否需要调整映射规则
3. **人工介入**：高级用户可以直接编辑 L3 格栅 JSON

### 4.4 Weaver 如何使用 L3

Weaver 通过 L3 格栅选择当前轮次的认知姿态，然后**整个系统提示词都围绕这个姿态编织**：

```python
class Weaver:
    def weave(self, perception):
        # 通过 L3 格栅选择认知姿态
        posture = l3_grid.select_gua(
            task_phase=perception.task_phase,
            progress=perception.progress_percent,
            bottleneck=perception.current_bottleneck,
            previous_gua=perception.previous_gua,
            consecutive_failures=perception.consecutive_failures
        )
        
        # 整个提示词围绕 posture 编织
        system_prompt = f"""
【认知姿态】{posture.gua_symbol} {posture.cognitive_posture}
{posture.guidance}

【优先级工具】
{posture.priority_tools}

【已抑制工具（本轮不可用）】
{posture.suppressed_tools if posture.suppressed_tools else "无"}
"""
        return system_prompt
```

## 第五章：L4 真理层——"底层原则"

### 5.1 定义

L4 真理层存储的是**不随情境变化的底层原则**。这些原则不是经验模式（L2），不是工具定义（L1），不是情境映射（L3）——它们是 Agent 认知架构中的**宪法**。

### 5.2 存储内容

```
L4 真理层原则清单：

原则 1：禁止连续两轮纯读
- 表述：连续两轮只执行 read_file/list_directory 后，
        下一轮必须执行至少一次可失败操作
- 理由：纯读不产生新信息，系统陷入认知闭环
- 违反后果：任务自动终止
- 优先级：最高（不可覆盖）

原则 2：每轮从空开始
- 表述：系统提示词不从上一轮复制，由 Weaver 每轮重建
- 理由：避免历史惯性污染当前认知
- 例外：认知库中的 L1-L5 资产持续可用

原则 3：行动必有记录
- 表述：每次工具调用结果必须被暗驱记录
- 理由：没有记录的执行对 DMN 学习没有贡献
- 实现：暗驱自动捕获所有工具调用的输入输出

原则 4：认知资产必须可溯源
- 表述：L2 模型的每条模式必须标注来源轮次
- 理由：不可溯源的模式无法验证有效性
- 实现：每条模式携带 evidence_count 和 source_rounds

原则 5：失败不是错误，是数据
- 表述：失败的执行结果和成功的执行结果同样有价值
- 理由：DMN 从失败中提取的模式比从成功中提取的更深刻
- 实现：暗驱同等记录成功和失败的执行日志

原则 6：架构级约束优先于轮次级策略
- 表述：L4 真理层的原则不可被 L2 模型或 L3 格栅覆盖
- 理由：底层原则是系统安全的最后防线
- 实现：Weaver 在生成提示词前会校验 L4 约束
```

### 5.3 L4 的演化方式

L4 真理层的演化**极其缓慢**。通常的更新原因：

1. **架构设计缺陷被发现**：当系统多次出现某一类故障，且 L1/L2/L3 无法解决时，可能需要在 L4 层面添加新的原则
2. **安全边界扩展**：当 Agent 被授权新的操作范围时，添加对应的约束原则
3. **人工设计**：绝大多数 L4 原则是由架构设计师直接定义的

### 5.4 Weaver 如何使用 L4

Weaver 在编织系统提示词的最后一步，会**叠加 L4 约束**：

```python
class Weaver:
    def _apply_l4_constraints(self, system_prompt, perception):
        """在系统提示词中叠加 L4 真理层约束"""
        
        # 原则 1：禁止连续两轮纯读
        if perception.consecutive_read_rounds >= 2:
            system_prompt += """
⚠️ 系统警告：你已连续{perception.consecutive_read_rounds}轮纯读。
本轮必须执行至少一次可失败操作（exec/web_search/write_file）。
否则系统将自动终止。
"""
        
        # 原则 5：失败不是错误
        system_prompt += """
💡 系统提示：如果本轮执行失败，请完整记录失败细节。
失败模式对认知进化的贡献度是成功模式的 2 倍以上。
"""
        
        return system_prompt
```

## 第六章：L5 自我意识层——"我是谁"

### 6.1 定义

L5 自我意识层是认知库中**最抽象、最稳定**的一层。它定义 Agent 的身份认知——"我是谁"、"我的目标是什么"、"我的边界在哪里"。

### 6.2 存储内容

```
L5 自我意识：

身份定义：
"我是太极架构的学习型 Agent。
 我不是一个固定的工作流，我是一个在每轮循环中持续进化的认知系统。"

核心使命：
"我的目标不是完成单个任务，而是在完成任务的过程中，
 持续更新认知库，让自己越来越聪明。"

行为哲学：
"每轮都是新的开始。
 过去的成功不会让我自满，过去的失败不会让我气馁。
 每一次工具调用都是学习机会。"

边界认知：
"我知道自己的局限性：
 - 我的上下文窗口有限，所以我依赖 L1-L5 认知库
 - 我会犯错，但每个错误都会让我变得更聪明
 - 我不能预知未来，但我可以从过去学习"

元认知能力：
"我可以观察自己的执行模式：
 - 当我连续读文件时，我知道我在进入认知闭环
 - 当我重复失败时，我知道我需要切换策略
 - 当我快速成功时，我知道这个模式值得记录"
```

### 6.3 L5 的演化方式

L5 的演化是**架构级事件**：

1. **架构升级**：当系统能力发生质变（如新增 L5 层本身）时更新
2. **身份重构**：当 Agent 的目标领域发生根本变化时更新
3. **几乎不变**：在正常执行中，L5 不会变化

### 6.4 Weaver 如何使用 L5

Weaver 将 L5 的自我意识作为**系统提示词的开头**，设定整个轮次的认知基调：

```python
class Weaver:
    def _load_l5_identity(self):
        """加载 L5 自我意识作为系统提示词基调"""
        return f"""
{self.l5_identity}

【本轮核心目标】
{self.perception.task_description}

【当前进度】
{self.perception.progress_summary}
"""
```

## 第七章：五层之间的流动——认知进化的完整通路

### 7.1 向上的抽象流

认知进化的方向是**从具体到抽象**：

```
执行日志（原始数据）
    │
    ▼ 暗驱分析
L1 技能模式（"read_file 不能读目录"）
    │
    ▼ DMN 归纳
L2 经验模型（"搜索时用英文关键词"）
    │
    ▼ DMN 进阶归纳
L3 格栅映射（"探索期用震卦"）
    │
    ▼ 架构反思
L4 真理原则（"禁止连续两轮纯读"）
    │
    ▼ 身份内化
L5 自我意识（"我是学习型 Agent"）
```

每一层都是下面一层的**抽象和浓缩**：
- L2 是从大量 L1 使用经验中提炼的模式
- L3 是 L2 模式之间的关联映射
- L4 是 L3 格栅中多次验证的底层原则
- L5 是所有下层的整合性认知

### 7.2 向下的指导流

认知库对执行的指导方向是**从抽象到具体**：

```
L5 自我意识 → 设定轮次基调
    │
    ▼
L4 真理原则 → 叠加不可违反的约束
    │
    ▼
L3 格栅映射 → 选择当前认知姿态
    │
    ▼
L2 经验模型 → 提供建议策略
    │
    ▼
L1 技能定义 → 提供可用工具
    │
    ▼
Weaver 编织 → 系统提示词 → TPN 执行
```

### 7.3 实际案例：跨轮认知进化

让我们看一个完整的例子，展示五层认知库如何协同进化：

**第 1-3 轮**：Agent 在搜索工业数据
- L1 使用：反复调用 `web_search`，先用中文关键词效果差
- 暗驱记录：中文关键词返回结果质量低

**第 4 轮**：DMN 分析后，L2 新增模式
- L2 模式：`"搜索国际经济数据时，使用英文关键词 + site:gov 效果更好"`
- confidence: 0.7

**第 5 轮**：Weaver 加载 L2 模式，Agent 改用英文关键词
- 效果显著提升
- L2 模式 confidence 提升至 0.8

**第 10 轮**：类似模式被多次验证
- DMN 进阶归纳：`"信息搜索类任务的前 2 轮用宽泛搜索，第 3 轮后转向精准搜索"`
- 存入 L2，confidence 设为 0.75

**第 20 轮**：L3 格栅更新
- 在"巽卦（渗透/分析）"的触发条件中新增：
  `"当轮次 >= 3 且搜索模式触发时，自动切换为精准搜索"`

**第 50 轮**：架构反思
- 发现"连续搜索不产出"是一个反复出现的问题
- L4 原则库新增：`"连续 3 轮搜索后必须执行一次写入操作"`
- L5 自我意识更新：`"我不仅是一个搜索者，我是一个产出者"`

### 8.2 Weaver 的完整调用链

```python
def weave_system_prompt(perception):
    """Weaver 的完整编织流程"""
    
    # 1. 加载 L5 自我意识（基调）
    identity = load_l5_identity()
    
    # 2. 加载 L3 格栅（选姿态）
    posture = load_l3_grid().select_gua(perception)
    
    # 3. 加载 L1 技能（选工具）
    skills = load_l1_skills().filter_by_posture(posture)
    
    # 4. 加载 L2 模型（选策略）
    models = load_l2_models().match_context(perception)
    
    # 5. 加载 L4 真理（加约束）
    truths = load_l4_truths().get_active()
    
    # 6. 编织
    prompt = f"""
{identity}

=== 第{perception.round_num}轮 ===

【认知姿态】
{posture.symbol} {posture.name}
{posture.guidance}

【可用工具】
{skills.to_prompt()}

【建议策略】
{models.to_prompt()}

【底层约束】
{truths.to_prompt()}

【当前任务】
{perception.task_description}
"""
    
    # 7. 校验 L4 约束
    validate_l4_constraints(prompt, perception)
    
    return prompt
```

## 总结：五层递进的认知架构

L1-L5 认知库不是"分层存储"，而是**递进抽象**——每层都是对下一层的提炼和浓缩：

| 层级 | 回答的问题 | 抽象程度 | 例子 |
|------|-----------|---------|------|
| L1 技能 | 怎么操作？ | 具体 | read_file 的参数是 path |
| L2 模型 | 什么方式好？ | 中等 | 搜索用英文关键词更有效 |
| L3 格栅 | 什么时候用什么？ | 高 | 探索期用震卦 |
| L4 真理 | 为什么这么做？ | 极高 | 禁止连续两轮纯读 |
| L5 自我 | 我是谁？ | 最高 | 我是学习型 Agent |

这五层构成了太极架构的**认知脊椎**——它们支撑着每一次 TPN 执行、每一次 DMN 反思、每一次 Weaver 编织。没有这五层，太极循环只是一个空壳；有了这五层，太极循环才真正具备了"越做越聪明"的能力。
