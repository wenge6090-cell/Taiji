# 基础篇·04：Weaver编织器——虚而待物，每轮从空开始动态织系统提示

> **核心论点**：主流 Agent 框架的 system prompt 是静态的——启动时加载，全程不变。太极架构的 Weaver 每轮从零开始编织系统提示词，基于当前认知状态动态选择策略、工具集和执行哲学。这不是"多了个组件"，而是一种全新的认知调度范式——「虚而待物」：空掉历史惯性，才能真实响应此刻需求。

---

## 引言：你的 Agent 是否戴着"昨天的眼镜"看今天的问题？

想象一个场景：

你正在用 AutoGPT 做一个市场调研任务。你告诉它："帮我分析2025年新能源汽车市场的竞争格局。"

第一轮，它搜索了行业报告，生成了初步分析。结果不错。

第五轮，任务从"分析市场"转向了"对比特斯拉和比亚迪的供应链策略"。但这时，Agent 的系统提示词（System Prompt）还是那个："你是一个市场调研助手，负责分析数据和生成报告。"

**问题出在哪？** 系统提示词——这个定义 Agent 角色、行为边界、执行哲学的"元指令"——在任务全程没有变化。它像一个固定滤镜，无论当前子任务是什么，Agent 都戴着同一副眼镜。

在主流框架中：
- **AutoGPT**：初始 prompt 定义了全部行为，循环执行时不变
- **LangGraph**：每个节点的 prompt 在图定义时固定，运行时不变
- **CrewAI**：每个角色的 prompt 在 Agent 注册时固定，协作时不变
- **OpenAI Assistants API**：instructions 在创建时设定，run 过程中不变

这种"固定系统提示词"的设计基于一个隐含假设：**执行框架可以提前预知 Agent 需要的一切认知姿态**。

但现实是：**Agent 在任务执行中遇到的状况，是设计时无法完全预料的。** 当任务从"收集信息"转向"深度分析"时，之前的"广泛探索"认知姿态可能不再适用。当任务遇到瓶颈需要破局时，之前的"稳定执行"策略可能成为障碍。

太极架构的解法是——**Weaver（编织器）**：每轮从空开始，基于当前认知状态动态编织系统提示词。

## 第一章：「虚而待物」——空，不是缺陷，是设计

### 1.1 从《庄子》到系统提示词

Weaver 的核心哲学源自《庄子·人间世》中的一句话：

> 「虚而待物，唯道集虚。虚者，心斋也。」

翻译成工程语言：**清空认知缓存，真实响应外部信号。**

庄子告诉颜回：在去见暴君之前，不要带着预设的立场（"心斋"——清空内心）。只有真正空掉自己的偏见，才能如实感知对方的状态，做出恰当的回应。

Weaver 的"空"体现在一个关键设计决策上：**每轮的系统提示词不从上一轮复制粘贴，不从历史缓存拼接，而是从零开始构建。**

```python
# 主流框架：追加式系统提示词
system_prompt = load_initial_system_prompt()  # 启动时加载
for round in range(100):
    # 系统提示词在整个生命周期不变
    agent.execute(system_prompt, task)

# 太极架构：Weaver 每轮重建系统提示词
for round in range(100):
    perception = mingjue.perceive(round)       # 评估当前状态
    system_prompt = weaver.weave(perception)   # 从零开始编织
    agent.execute(system_prompt, task)         # 使用新编织的提示词
```

**每轮都是新的。** 这听起来违背直觉——为什么要每轮重建？复用上一轮的提示词不是更节省 token 吗？

答案就在"虚而待物"四个字中：**只有空掉上一轮的认知姿态，才能真实响应这一轮的认知需求。**

### 1.2 "空"的三层含义

**第一层空：空掉历史惯性**

假设你前5轮都在用"乾卦——创造/突破"姿态：大胆假设、快速试错、广泛探索。

第6轮，任务进入了"需要稳定输出成果"的阶段。但如果你保留着第5轮的提示词，其中的"大胆探索"指令会继续影响 Agent 的行为——即使你已经换了一个任务子目标。

这就是**历史惯性**：过去成功的策略成为当前执行的"舒适区"。

Weaver 的"每轮从空开始"强制打破了这种惯性。第6轮的 Weaver 将读取当前明觉评估——"任务已进入产出期"——然后选择"兑卦——表达/输出"姿态，编织完全不同的提示词。

**第二层空：空掉认知预设**

每个 Weaver 编织的提示词中，都包含当前轮次的"认知姿态"定义。但这个姿态不是 Weaver 自己选择的——它来源于 L3 格栅（八卦认知网格）和明觉的当前评估。

Weaver 自己没有任何"偏好"。它不会说："我喜欢乾卦，所以总用乾卦。"它只是一个**认知映射器**——将当前状态映射到对应的认知策略。

这类似于"无我"——Weaver 没有自己的议程，它完全服务于当前任务的需求。

**第三层空：空掉固定工具集**

大多数框架在启动时加载全部工具。Weaver 的做法是：**只有当前认知姿态需要的工具，才会被加载到系统提示词中。**

一个处在"兑卦（表达/产出）"姿态的 Agent，系统提示词中不会包含搜索工具——因为它的目标是产出，不是探索。一个处在"震卦（启动/收集）"姿态的 Agent，其提示词中不会包含写作工具——因为它的目标是收集，不是生成。

这种动态工具裁剪，保证了 Agent 不会因为"工具诱惑"而偏离当前轮的认知目标。

## 第二章：Weaver 的编织工艺——从原材料到系统提示词

### 2.1 原材料的四道工序

Weaver 的"编织"不是随机拼凑。它遵循一个固定的工序流程，将四类原材料整合为一份系统提示词：

```
原材料 → 织认知策略 → 织工具集 → 织执行指导 → 织跨轮记忆 → 系统提示词
```

**工序一：读取明觉评估（感知上下文）**

明觉（Mingjue）在每一轮开始时评估当前状态，产出评估报告。Weaver 读取这份报告，获取三个关键信息：

1. **任务生命周期相位**：任务处于生/长/育/化/收/藏/安/复的哪个阶段？
2. **当前进度和瓶颈**：完成了多少？卡在哪里？
3. **相邻轮次的状态**：上一轮做了什么？结果如何？

**工序二：查询 L3 认知格栅（选择策略）**

Weaver 将明觉评估映射到 L3 格栅中的八卦认知网格。每个卦象对应一套完整的认知策略：

| 卦象 | 认知姿态 | 适用场景 | 核心指令 |
|------|---------|---------|---------|
| ☰ 乾 | 创造/开天 | 需要从0到1突破 | "你的任务是创造，不是复制" |
| ☷ 坤 | 承载/执行 | 需要稳定积累 | "扎实就是效率" |
| ☳ 震 | 启动/激发 | 任务起步或卡住 | "快速启动，广泛收集" |
| ☴ 巽 | 渗透/分析 | 需要深度洞察 | "不是表面浏览，而是渗透理解" |
| ☵ 坎 | 破局/挑战 | 遇到瓶颈需突破 | "打破常规，挑战预设" |
| ☲ 离 | 明照/评估 | 需要清点现状 | "照亮现状，清晰评估" |
| ☶ 艮 | 止定/聚焦 | 范围过散需收敛 | "停下来，聚焦核心" |
| ☱ 兑 | 表达/输出 | 需要交付成果 | "表达，发布，交付" |

**工序三：绑定 L1 技能和 L2 模型（加载能力）**

认知姿态确定后，Weaver 查询当前卦象关联的 L1 技能和 L2 模型：

```
当前卦象: ☲ 离（明照/评估）
→ 关联 L1 技能: 目录浏览(read_file/list_directory), 内容分析(grep), 状态评估
→ 关联 L2 模型: "评估模式"（包含评估工作流模板和分析框架）
→ 加载到工具定义: read_file, list_directory, exec(grep)
```

**工序四：注入暗驱提炼的模式（传承经验）**

暗驱（Anqu）在上一轮执行完毕后，提取了核心经验模式。Weaver 将这些模式注入新的提示词：

```
暗驱第3轮提取的模式：
——"宽泛搜索在任务初期有效，但第3轮后需要聚焦"
——"连续两轮纯读后，必须执行一次可失败操作以打破惯性"

→ Weaver 将其编织进第4轮提示词：
"注意：你已连续3轮纯读。本轮必须执行至少一次可失败操作（搜索/写入/执行），
否则系统将触发硬约束中断。建议切换到震卦（启动）或兑卦（产出）。"
```

### 2.2 编织出的系统提示词长什么样？

以下是一个由 Weaver 编织出的真实系统提示词样例（简化版）：

```
=== 太极架构第7轮系统提示词 ===

【认知姿态】
当前卦象：☱ 兑卦（表达/输出）
执行哲学："表达、发布、交付——你的目标不是探索更多，而是将已有材料转化为结构化产出。"
节奏提示："效率优先。不要追求完美，追求完成。"

【可用工具】
你当前可用的工具列表：
1. write_file — 写入Markdown文件（当前轮首选）
2. edit_file — 编辑已有文件
3. read_file — 读取文件验证内容
4. list_directory — 浏览目录结构

*注意：搜索工具本轮已禁用——你的任务是产出，不是探索。*

【执行指导】
当前生命相位：收（收敛/产出）阶段
工作流步骤：
1. 评估已有材料是否足够
2. 选择需要产出的文件
3. 写入内容
4. 读取验证
5. 如有问题，编辑修正

【跨轮记忆】
上一轮（第6轮，☳ 震卦）执行回顾：
— 成功收集了12个框架的比较信息
— 暗驱提炼：收集阶段已完成，建议转换为产出模式
— 注意：产出质量比数量重要

【安全约束】
- 禁止删除已有文件
- 禁止执行未批准的shell命令
- 连续两轮纯读将触发硬约束中断

=== 提示词结束 ===
```

每一项都是 Weaver 从当前状态动态生成的——不是从固定模板复制粘贴，而是"虚而待物"地对当前需求做出响应。

## 第三章：从"空"开始的工程实践——Weaver 在太极中的实际运行

### 3.1 案例一：跨境工业信息差的六轮循环

让我们跟踪一个真实任务——收集跨境工业零部件信息差——看看 Weaver 如何在六轮中持续切换认知姿态：

**第1轮：☳ 震卦（启动/收集）**

明觉评估："任务刚启动，需要快速收集基础信息"

Weaver 编织的提示词包含：
- 工具集：web_search, read_file, list_directory（搜索工具优先）
- 策略："广泛搜索，不要过早聚焦"
- 节奏："第一轮优先了解全貌，不要深入细节"

**第2轮：☴ 巽卦（渗透/分析）**

明觉评估："已收集基础信息，需要深入理解结构"

Weaver 编织的提示词：
- 工具集：read_file, grep, 数据提取（搜索工具被排除）
- 策略："不是表面浏览，而是渗透理解——读深，不读广"
- 跨轮记忆："第1轮收集了12个框架，但结构杂乱——本轮请结构化整理"

**第3轮：☷ 坤卦（承载/执行）**

明觉评估："分析完成，需要稳定产出分析报告"

Weaver 编织的提示词：
- 工具集：write_file, edit_file（唯一可用工具）
- 策略："不要追求创新——把已有策略执行到极致"
- 节奏："扎实就是效率"

**第4轮：☵ 坎卦（破局/挑战）**

明觉评估："分析报告已完成，但核心数据缺失，任务陷入瓶颈"

Weaver 编织的提示词：
- 工具集：web_search（特定搜索），exec（脚本抓取）
- 策略："打破常规——尝试之前没有用过的搜索路径"
- 跨轮记忆："之前的搜索策略过于泛泛——请尝试垂直搜索"

**第5轮：☱ 兑卦（表达/输出）**

明觉评估："关键数据已补充，可以产出最终报告"

Weaver 编织的提示词：
- 工具集：write_file（唯一）
- 策略："表达、发布、交付"
- 约束：禁止搜索、禁止深挖——产出先行

**第6轮：☲ 离卦（明照/评估）**

明觉评估："报告已产出，需要评估质量"

Weaver 编织的提示词：
- 工具集：read_file, diff
- 策略："照亮现状，清晰评估"
- 节奏："评估质量，标注改进点，但不要修改"

这个案例展示了 Weaver 的核心能力：**它不是"自动选卦"的开关，而是一个实时响应认知需求的编织器。** 每一轮的提示词都是全新的，但都承接着上一轮的学习结果。

### 3.2 案例二：银发经济全自动流水线中的 Weaver

在银发经济自动化任务中，Weaver 面临更复杂的挑战——任务生命周期更长（30轮），认知切换更频繁：

```python
# Weaver 在银发经济任务中的决策日志（简化）
Round  1: 震卦 — 启动，快速收集银发经济政策信息
Round  2: 巽卦 — 深度分析政策文档，提取关键条款
Round  3: 坤卦 — 稳定写入政策分析报告
Round  4: 离卦 — 评估报告质量，发现缺少案例支撑
Round  5: 震卦 — 重新启动，搜索真实案例
Round  6: 巽卦 — 渗透分析案例，提取模式
Round  7: 坤卦 — 执行，补充案例到报告
Round  8: 兑卦 — 表达，格式化最终报告
Round  9: 离卦 — 评估，检查完整性
Round 10: 艮卦 — 止定，收敛范围，聚焦核心章节
...
```

关键观察：**Weaver 不是按照固定序列切换，而是根据每轮的明觉评估动态决策。** 在第4轮发现案例缺失时，它没有继续产出（兑卦），而是切回启动模式（震卦）补充材料。

这种动态切换能力——去历史惯性——正是"虚而待物"的工程体现。

## 第四章：Weaver 与传统框架的对比

### 4.1 静态提示词 vs 动态编织

| 维度 | 传统框架（AutoGPT/LangGraph） | 太极 Weaver |
|------|-------------------------------|-------------|
| 系统提示词 | 启动时加载，全程不变 | 每轮从零编织 |
| 工具集 | 所有工具始终可用 | 按认知姿态动态裁剪 |
| 认知策略 | 固定角色定义 | 八卦认知网格动态选择 |
| 历史使用 | 原始历史拼接（上下文爆炸） | 有损压缩（暗驱提炼模式） |
| 响应变更 | 无法响应任务子目标切换 | 每轮重新评估并调整 |
| Token 消耗 | 初始少，但上下文快速增长 | 每轮新提示词（约1-2K tokens） |

### 4.2 为什么 Weaver 的 token "浪费"是值得的

反对者会说："每轮重建系统提示词太浪费 token 了！一次构建重复用不是更高效吗？"

这是一个合理的工程质疑，答案体现在两个层面：

**层面一：上下文效率 vs 认知效率**

传统框架的"token 节省"是假象——它们确实生成了更少的系统提示词，但上下文窗口中被无效历史填满的速度更快。

以 AutoGPT 为例：第10轮时，上下文包含10轮的全部思考、执行结果、观察记录——其中90%对当前轮次无用。Agent 必须在噪声中找到信号。

而 Weaver 每轮只消耗约1-2K tokens 的新提示词，且不拼接历史。DMN 提供的"有损压缩"经验只有几百 token。整体 token 消耗并不更高。

**层面二：认知灵活性的价值**

如果你的任务只有3轮，静态提示词就够用。但如果你的任务需要10轮、30轮、甚至300轮——任务子目标可能发生根本性变化。

一个从"收集"切换到"产出"的任务，如果系统提示词不变，Agent 会继续搜索——即使它应该开始写作了。这种"认知惯性"导致的效率损失，远大于 Weaver 每轮重建提示词的 token 消耗。

**Weaver 不是"更贵"的选择——它是在长程任务中"唯一可行"的选择。**

## 第五章：「虚而待物」的深层哲学

### 5.1 老子与 Weaver

> 《道德经》第十六章：「致虚极，守静笃。万物并作，吾以观复。」

翻译到极致：**空到极致，静到笃定。万物生长，我观其循环回归。**

Weaver 的"每轮从空开始"，本质上就是对"致虚极"的工程实现。

- **致虚极**：每轮清空历史惯性，不从上一轮复制认知姿态
- **守静笃**：不追逐每一个新想法，只根据明觉评估做出认知选择
- **观复**：通过暗驱提炼的模式观察轮回中的规律，不断优化认知策略

### 5.2 工程师的"心斋"

《庄子》的"心斋"有一个更直接的工程类比：

> 「若一志，无听之以耳而听之以心，无听之以心而听之以气。听止于耳，心止于符。气也者，虚而待物者也。唯道集虚。虚者，心斋也。」

翻译：**专注你的心志。不要用耳朵听（表面感知），要用心听（认知分析）；不要用心听，要用"气"听（直接响应）。耳朵只能接收声音，心智只能匹配模式。"气"是虚而待物的——只有空才能接住道。**

Weaver 就是太极架构的"气"——它不通过搜索（耳）或分析（心）来理解任务，而是通过清空自己（虚）来直接响应任务的真实需求（待物）。

当一个工程师写出的系统提示词能够"空掉历史"，他的 Agent 才能真正"看见"当前的挑战。

---

## 结语：Weaver 不是组件，是认知原则

Weaver 不是一个"可以去掉的组件"。它是太极架构存在的基础。

没有 Weaver，太极就退化为一个"带八卦的 LangGraph"——多了一个装饰，但本质上还是静态的工作流编排。

Weaver 将老子的"无为"、庄子的"心斋"、易经的"变易"融入了工程实践。它证明了一个反直觉的真理：

> **为了让系统能学习，每轮都必须从空开始。**

这不是浪费，而是"虚而待物"的智慧——只有空掉昨天，才能真实面对今天。
