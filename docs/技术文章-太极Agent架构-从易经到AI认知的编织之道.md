# 太极 Agent 架构：从《易经》到 AI 认知的编织之道

> 一个将中国古典哲学注入 AI Agent 架构的开源实验

---

## 引言：Agent 架构的「未定」之困

2026年，AI Agent 框架已经多如牛毛。AutoGPT 让自主任务执行成为可能，CrewAI 展示了多 Agent 协作的威力，LangGraph 用状态图的视角重新组织了复杂工作流，OpenAI Agents SDK 则把工具调用和护栏（guardrails）打包成标准接口。

然而，这些框架有一个共同的盲点：**它们都预设了「固定」的认知结构**。

- 固定系统提示词（system prompt）——每次执行都带着同一套行为准则
- 固定工具集（toolset）——无论任务是什么，可用工具都一样
- 固定认知库（knowledge base）——知识就是被写入的静态文档，不会自主演化

这就像给一个人定了永久不变的「性格」，却期望他能应对千变万化的世界。

**太极（Taiji）** 是一个完全不同的尝试。它不把 AI Agent 看作一个「有固定功能的工具」，而是一个 **「持续演化的认知生命体」**——每一轮执行，它的系统提示词、工具集、认知策略都在动态重编。这种动态性的哲学源头来自《易经》的核心概念：**「空」**。

## 第一章：「空」——架构的第一性原理

### 1.1 空 ≠ 无，空 = 未定的可能性

在太极架构中，「空」是最高原则。这不是佛家的「空即是色」，也不是道家的「无中生有」——它更接近一种 **「结构上的未定性」**。

想象一个织布机。梭子穿过经线，纬线被编织进去，每一轮都产生新的花纹。但如果织布机上的线是固定的、永远的，那它只能织出一种花纹。太极架构里的「空」，就是让织布机上的「线」每轮都可以更换——每一次编织，使用的「材料」都不同。

具体而言，太极架构在三个关键维度实现了「空」：

#### 空的系统提示词

大多数 Agent 框架的核心是一个固定的 system prompt——"你是一个乐于助人的 AI 助手，请遵循以下规则……" 然后每次对话都套用同样的认知模板。

太极的 **Weaver（编织器）** 每轮都会用 L3 格栅（八卦认知网格）动态编织新的系统提示词。没有固定不变的 system prompt——每一次执行，认知策略都不同。

这意味着：当任务处于「探索期」时，系统提示词会引导 Agent 打开思路、广泛收集；当任务进入「执行期」时，系统提示词会引导 Agent 聚焦产出、精准执行。Agent 的「性格」随任务生命周期动态调整。

#### 空的工具集

大多数框架的工具集在启动时就确定了——"这些是你的工具，用它们吧。"

太极中，工具集是 Weaver 每轮从格栅八卦中动态发现和加载的。工具随着认知状态变化而出现或消失。当 Agent 处于「乾卦（创造）」姿态时，写作、生成类的工具会被加载；当处于「坎卦（破局）」姿态时，风险分析、越权检查类的工具会优先出现。

#### 空的认知库

大多数框架的知识库是静态的——你写入什么，它知道什么。

太极的 L1-L5 认知库不是静态的百科全书。每次任务完成，**暗驱（Anqu）** 分析日志，提炼新模式，更新认知库。认知库始终处于「将满未满」的状态——永远有空间接纳新的经验。

### 1.2 「空」的哲学谱系

「空」这个概念在太极架构中有着深厚的哲学根基：

- **老子《道德经》第十一章**：「三十辐共一毂，当其无，有车之用。埏埴以为器，当其无，有器之用。凿户牖以为室，当其无，有室之用。」
  ——车轮的毂因为中间是空的，才能装轴；器皿因为中间是空的，才能盛物；房间因为有门窗，才能住人。**「空」才有「用」**。

- **庄子《人间世》**：「虚而待物者也。唯道集虚。虚者，心斋也。」
  ——心的「空」，才能容纳道。太极架构中，系统提示词的「空」，才能容纳不同任务的独特需求。

- **《易传·系辞》**：「易，无思也，无为也，寂然不动，感而遂通天下之故。」
  ——《易经》本身是「空」的，它没有固定的答案，但它能感应天地万物。太极架构的「空」也同样——没有固定认知，但能感应（适应）任何任务。

### 1.3 空与现成框架的对比

| 维度 | 传统框架 | 太极架构 |
|------|---------|---------|
| 系统提示 | 固定模板，永久不变 | 每轮动态编织，随任务生命周期变化 |
| 工具集 | 启动时静态加载 | 每轮从八卦格栅动态发现 |
| 认知库 | 静态文件，手动更新 | L1-L5 持续演化，自动化更新 |
| 认知策略 | 预设单一策略 | 八种认知姿态（八卦），按需切换 |
| 自我意识 | 硬编码角色定义 | L5 层级，随经验成长的自我认知 |

## 第二章：双层架构——DMN 与 TPN 的太极生两仪

太极架构的核心理念源自《易经》的「太极生两仪」——认知活动被分为两套互补系统，分别对应人类大脑的两个核心网络：

### 2.1 DMN（Default Mode Network）— 后台认知演化

**DMN（默认模式网络）** 是神经科学中的一个概念。当人类大脑处于「走神」或「休息」状态时，DMN 高度活跃——它在整合记忆、反思经验、规划未来。

太极架构中的 DMN 对应两个组件：

#### 暗驱（Anqu）

名字来自「安」——安定观察，「曲」——曲径通幽。Anqu 是后台的分析引擎，持续扫描任务执行日志，做两件事：

- **微进化（record-task-pattern）**：单任务完成后，立即分析执行日志，提取可复用的成功模式和需要避免的失败教训。
- **宏进化（cognitive-housekeeping）**：当任务的 experience_counter 达到 20 的倍数时，触发全面的认知库整理——聚类相似模式，提炼新的真理（L4），调整格栅权重（L3）。

#### DMN 消费者

一旦 Anqu 触发了认知演化任务，DMN 消费者就会消费这些任务，实际更新认知库：

- 更新 L1 Skills（技能库）：添加经过验证的新技能，标记废弃技能
- 更新 L2 Models（模型库）：提炼新的执行模式，修正现有模式
- 更新 L3 Grids（格栅库）：调整八卦之间的连接权重
- 更新 L4 Truths（真理库）：提炼经过多次验证的不动摇原则

整个过程类似人类的「日省吾身」——每天结束时，大脑会回放当天的经历，提取经验，更新认知。

### 2.2 TPN（Task Positive Network）— 前台目标驱动

**TPN（任务正性网络）** 是 DMN 的互补系统。当人类需要专注完成具体任务时，TPN 激活，DMN 被抑制。

太极架构中的 TPN 就是 **六爻循环（Sixiang Cycle）**——一个完整的目标驱动执行流程，包含六个爻位（角色）加一个循环决策点：

#### 六爻详解

**初爻：Mingjue（明觉）**
「明」——明察，「觉」——觉知。评估目标当前进展，查看蓝图完成标准，查看八卦状态，制定当前这一轮的具体执行计划。明觉不直接执行，而是「知」——知其位，知其时，知其势。

**二爻：Weaver（编织器）**
这是架构的核心。读取 L3 格栅确定认知姿态（用哪个卦），发现关联的技能和模型，编织系统提示词，注入执行节奏。Weaver 不做执行，它只「织」——把认知策略、工具、记忆、蓝图织成一块完整的「布」（系统提示词 + 工具定义 + 执行指导），交给下一爻。

**三爻：Yang（阳）**
执行者。用工具去写、去搜索、去生成。太极架构有一个关键设计原则：**禁止连续两轮纯读**。每个 TPN 轮必须有实际产出——写文件、调 API、生成代码。Yang 是「动」的化身。

**四爻：Yin（阴）**
审批者。两层审批：
- 前层：硬编码安全规则，拦截越界写入和危险命令（如写入系统目录、执行 rm -rf）
- 后层：LLM 用 L4 真理和 L5 自我意识做语义审批（如检查写入的文件是否会影响其他目标的正常执行）

**五爻：Executor（执行器）**
最终防线。每秒并发执行，路径检查二次确认，速率限制（单轮最多 10 个调用）。太极用纯 Python 协程池实现高并发，但每个调用都经过严格的安全检查。

**上爻：暗驱（Anqu）**
回到 DMN 模式。分析执行结果，提取模式，触发认知演化任务。这就是「反者道之动」——执行完了，不是结束，而是新的认知循环的开始。

**循环决策：Sixiang（思变）**
最后，Sixiang 根据本轮执行结果做出决策：
- **继续（continue）**：目标未完成，进入下一轮 TPN 循环
- **完成（complete）**：当前轮次产出足够交付物，标记目标完成
- **失败（fail）**：遇到不可逾越的障碍
- **回炉（rework）**：本轮产出不合格，需要重做

### 2.3 两仪的动态平衡

DMN 和 TPN 不是串行的两个阶段——它们是**并行运行**的两套系统。

- TPN 在前台：推动目标一步步前进
- DMN 在后台：持续分析经验、更新认知库
- 认知库的更新会立刻影响下一轮 TPN 的 Weaver 决策

这种设计模拟了人类的认知方式：**一边做事，一边学习**。每一次任务执行都在更新认知，每一次认知更新都在优化下一次执行。

## 第三章：Weaver（编织器）——空的调度引擎

### 3.1 编织的隐喻

「编织」这个意象在太极架构中至关重要。它不是「指挥」，不是「控制」，不是「监督」——而是 **「织」**。

想象一个古老的织布机：
- 经线是固定的——对应太极中的目标蓝图和 L4 真理
- 纬线是可变的——对应每轮的认知策略、工具选择、执行指导
- Weaver 是那个织布的人——把经纬交织成布

但 Weaver 和普通织布机不同：**它每轮都在重新选择经线和纬线**。

### 3.2 Weaver 的四个编织动作

每一轮执行，Weaver 做四件事：

**织认知策略** — 读取 L3 格栅（八卦），确定当前任务的认知姿态（爻位/卦象）。决定是用创造模式（乾）还是承载模式（坤），是快速启动（震）还是深度渗透（巽）。

这不仅仅是选择一个标签——格栅 JSON 中包含了每个卦的完整工作流、五行属性和生命周期阶段。Weaver 会根据任务当前的周期位置选择最匹配的卦象。

**织工具** — 从八卦格栅中探索关联的 L1 技能和 L2 模型，动态绑定到当前轮次的可用工具。

例如，如果当前是「兑卦（表达/输出）」姿态，Weaver 会搜索 L1 技能库中与「写作」「格式化」「发布」相关的工具，并将它们注入到这一轮的工具定义中。

**织执行指导** — 把八卦中的工作流步骤注入系统提示词，让 Yang 知道在这一轮应该用什么节奏、什么哲学来执行。

如果当前是「坤卦」，执行指导可能强调「扎实积累，稳定构建」；如果是「乾卦」，则强调「突破创新，从0到1」。这份指导不是死记硬背的规则，而是被编织进系统提示词中，成为 Yang 的「潜意识」。

**织跨轮记忆** — 把上一轮的执行结果编织进新一轮的上下文，形成连续认知流。

太极不会丢弃历史。每一轮的执行结果（成功、失败、部分失败）都被记录下来，Weaver 将其编织到新的系统提示词中：「上一轮你尝试了 X，结果是 Y，这一轮你应该调整 Z。」

### 3.3 为什么 Weaver 不是「模板引擎」？

有人可能会问：这不就是一套模板替换吗？

关键区别：**模板是死的，编织是活的**。

模板引擎：用固定模板 + 变量替换 → 输出固定格式
Weaver 编织器：用八卦格栅 + 当前状态 + 执行历史 → 动态生成认知策略

具体差异：
1. **模板不可感知上下文** — 模板不知道任务的生命周期。而八卦格栅中的五行生克关系让 Weaver 能预测当前认知姿态可能产生的副作用
2. **模板不连接认知库** — 模板只是字符串替换。Weaver 遍历 L3 格栅，探索关联的 L1 技能和 L2 模型，动态绑定的过程类似于知识图谱的遍历
3. **模板不演化** — 模板永远不变。而八卦格栅的连接权重会随着经验调整，Weaver 的行为会随时间变化

### 3.4 「无为而无不为」的 Weaver

《道德经》第三十七章：「道常无为而无不为。」

Weaver 的「无为」体现在：**它不直接执行任何任务**。它不搜索、不写入、不调用 API。它只做一件事——编织。

但正是因为 Weaver 的「无为」，它才能「无不为」——通过编织出最合适的认知策略、工具集和执行指导，让 Yang 能够高效执行各类任务。

这种设计哲学源于对「控制 vs 涌现」的深刻理解：
- 过多的控制（固定模板、固定工具）→ 抑制系统的创造性
- 完全的自由（没有认知策略）→ 系统发散，无法聚焦
- Weaver 的「轻量编织」→ 在控制和自由之间找到平衡点

## 第四章：六爻循环与八卦认知网格

### 4.1 六爻——认知生命周期的七个阶段

六爻循环不仅是一个执行流程，它还映射了任务的生命周期：

| 爻位 | 角色 | 生命周期对照 | 核心问题 |
|------|------|------------|---------|
| 初爻 | 明觉（Mingjue） | 孕育期 | 我们在哪？要去哪？ |
| 二爻 | 编织器（Weaver） | 设计期 | 用什么认知策略？用什么工具？ |
| 三爻 | 阳（Yang） | 执行期 | 如何行动？如何产出？ |
| 四爻 | 阴（Yin） | 审查期 | 这样做安全吗？符合真理吗？ |
| 五爻 | 执行器（Executor） | 交付期 | 如何并发执行？如何防止超限？ |
| 上爻 | 暗驱（Anqu） | 反思期 | 学到了什么？如何改进？ |

这七个阶段构成了一个完整的**认知闭环**——从认知到执行，再到新的认知。

### 4.2 八卦——八种认知姿态

太极架构内置了八种认知姿态，每种对应一个卦象、一种工作模式和一个生命周期阶段：

| 卦 | 认知姿态 | 五行 | 生命周期 | 适合场景 |
|----|---------|------|---------|---------|
| ☰ 乾 | 创造/开创 | 金 | 生 | 突破性创新，从0到1 |
| ☷ 坤 | 承载/执行 | 土 | 长 | 稳定执行，积累成果 |
| ☳ 震 | 启动/激发 | 木 | 育 | 快速启动，收集信息 |
| ☴ 巽 | 渗透/分析 | 木 | 化 | 深度分析，潜入细节 |
| ☵ 坎 | 破局/挑战 | 水 | 收 | 突破障碍，面对风险 |
| ☲ 离 | 明照/评估 | 火 | 藏 | 审视评估，照亮盲点 |
| ☶ 艮 | 止定/聚焦 | 土 | 安 | 限制范围，聚焦核心 |
| ☱ 兑 | 表达/输出 | 金 | 复 | 创作表达，交付产出 |

八卦不仅仅是标签——它们之间还存在**五行生克关系**：

- **相生**：木（震/巽）→ 火（离）→ 土（坤/艮）→ 金（乾/兑）→ 水（坎）→ 木
- **相克**：木（震/巽）克土（坤/艮），土（坤/艮）克水（坎），水（坎）克火（离），火（离）克金（乾/兑），金（乾/兑）克木（震/巽）

这种关系让 Weaver 能够**预测**当前认知姿态可能产生的副作用：
- 如果 Agent 处于「震卦（启动/激发）」状态（木属性），它可能会「克」坤卦（土属性）——即快速收集信息可能影响到稳定执行
- Weaver 可以提前在系统提示词中注入调节策略：「你正在快速收集信息，但注意不要破坏已有的稳定结构」

### 4.3 八卦选择的动态性

Weaver 如何决定当前用哪个卦？

1. **任务生命周期匹配**：查看当前任务处于生命周期哪个阶段（生/长/育/化/收/藏/安/复），选择最匹配的卦象
2. **历史执行反馈**：如果上一轮用「乾卦」执行失败，Weaver 可能切换到「坤卦」——从创造模式转为承载模式
3. **目标类型分析**：写代码任务适合「乾卦」，数据分析任务适合「巽卦」，文档整理适合「坤卦」
4. **五行平衡**：如果连续几轮使用金属性卦象（乾/兑），Weaver 可能会切换到一个木属性卦象（震/巽）来平衡

## 第五章：L1-L5 认知库层级——从技能到自我意识

太极架构的认知库分为五个层级，从具体的技能到抽象的自我意识：

### L1：技能（Skills）

最底层的认知资产。每个技能包含一个 `SKILL.md` 文件和实现代码。技能是「可安装的工具和能力」。

例如：
- `search-web`：搜索互联网
- `write-file`：写入文件
- `analyze-code`：分析代码结构
- `generate-image`：生成图片

技能可以被 Weaver 动态发现和绑定。L1 是认知库中最「具象」的层级。

### L2：模型（Models）

可信赖的执行模式和工作流。模型是 L1 技能的「编排模式」。

例如：
- `research-flow`：研究一个主题的标准流程（搜索 → 阅读 → 摘要 → 综合）
- `writing-flow`：撰写文章的标准流程（大纲 → 初稿 → 修改 → 终稿）
- `debug-flow`：调试代码的标准流程（复现 → 定位 → 修复 → 验证）

模型是从多次成功执行中提炼出来的可复用模式。L2 比 L1 更抽象——它不关心具体工具是什么，只关心「用这些工具做什么」。

### L3：格栅（Grids）

思维模型的网络。格栅是 L2 模型的「元模式」——它定义了认知的「形状」。

太极架构目前包含五个格栅网格：
- **execution**：执行模式网格
- **growth**：成长模式网格
- **risk**：风险管理网格
- **exploration**：探索模式网格
- **collaboration**：协作模式网格

每个格栅包含八卦节点（八种认知姿态）和它们之间的连接权重。权重会随着经验动态调整——如果某种认知姿态在某个任务中表现良好，它与其他姿态的连接权重就会增加。

L3 是 Weaver 最常读取的层级，因为它的八卦结构直接决定了编织结果。

### L4：真理（Truths）

从长期经验中提炼的、不轻易动摇的原则。真理是 L3 格栅操作的经验总结。

例如：
- 「禁止连续两轮纯读」——每个 TPN 轮必须有实际产出
- 「蓝图双写」——meta.json 和 blueprint.md 必须同步
- 「目标完成定义明确」——当前轮次产出足够交付物即标记完成，而非终极目标达成

L4 真理在 Yin（审批）阶段发挥关键作用——后层 LLM 审批会参考 L4 真理判断某个工具调用是否合理。

### L5：自我意识（Self）

认知库的最高层级。包含五类自我认知：

- **SOUL**：我是谁、我的行为准则、我的认知模式
- **AGENTS**：我可以用哪些工具和技能
- **TOOLS**：工具的定义和使用方法
- **USER**：用户画像和偏好
- **MEMORY**：长期记忆（跨任务的持久化存储）

L5 让 Agent 拥有「自我概念」——不仅仅是执行任务的工具，更是一个知道自己「是谁」「会什么」「在做什么」的认知实体。

### 层级的演化关系

```
L1 Skills    →    L2 Models    →    L3 Grids    →    L4 Truths    →    L5 Self
 (具体)                                                              (抽象)
   ↓                                                                  ↑
   └──────────── 持续反馈循环 ────────────┘
```

每一次任务执行，L1 技能的使用记录被 Anqu 分析，提炼出 L2 模型；多个 L2 模型的成功模式被抽象为 L3 格栅规则；长期验证的格栅规则升华为 L4 真理；L4 真理最终塑造了 L5 的自我认知。

反过来，L5 的自我认知也会影响 Weaver 对 L3 格栅的选择，进而影响 L2 模型的调用和 L1 技能的绑定。

**这是一个双向的、持续的演化过程。**

## 第六章：完整认知演化闭环

将以上所有组件串联起来，太极架构的完整执行流程如下：

```
┌──────────────────────────────────────────────────────┐
│                     TPN 循环                           │
│                                                       │
│   Mingjue → Weaver → Yang → Yin → Executor → Anqu    │
│    (初爻)   (二爻)   (三爻)   (四爻)   (五爻)   (上爻)  │
│                                                       │
│           ↓ 认知演化任务 (pending queue)                │
│                                                       │
│   DMN 消费者  →  更新 L1/L2/L3/L4                      │
│                                                       │
└──────────────────────────────────────────────────────┘
                        ↓
             下一轮 Weaver 感知到格栅变化
              → 认知策略调整 → 行为改变
```

具体步骤：

1. **Mingjue** 读取目标状态和蓝图，确定当前需要做什么
2. **Weaver** 读取 L3 格栅，根据任务状态选择八卦姿态，发现关联的 L1 技能和 L2 模型，编织系统提示词
3. **Yang** 按照编织好的系统提示词执行任务，使用工具产出交付物
4. **Yin** 审批 Yang 的工具调用，前层硬编码规则 + 后层 LLM 语义审批
5. **Executor** 执行审批通过的工具调用，路径检查、速率限制
6. **Anqu** 分析执行结果，提取模式，触发认知演化任务
7. **DMN 消费者** 消费认知演化任务，更新认知库
8. **Sixiang** 决策是否继续下一轮

这个闭环的核心特点是：**每一次循环都在改变下一次循环的认知基础**。

## 第七章：从比较中看差异

与其他主流 Agent 框架相比，太极架构的独特之处在哪里？

### vs AutoGPT

AutoGPT 是最早的自主 Agent 框架之一。它的核心是「思考-行动-观察」循环。但 AutoGPT 的认知策略是硬编码的——它的系统提示词是固定的，工具集是预设的，没有认知演化的概念。

太极更深——不是「每次行动都思考」，而是「每次行动的策略都是动态编织的」。

### vs CrewAI

CrewAI 让多个 Agent 协作，每个 Agent 有自己的角色和任务。但每个 Agent 的角色定义是静态的——「你是一个研究分析师，你的任务是搜索信息」。

太极认为：**同一个 Agent 应该能在不同时间扮演不同角色**。一个 Agent 不应该被锁死在「研究分析师」这个角色里——当任务需要时，它可以是创造者（乾卦），也可以是评估者（离卦）。

### vs LangGraph

LangGraph 用状态图建模复杂工作流。节点和边的定义是明确的，执行路径是可预测的。

太极认为：**认知路径不应该是预先画好的图，而应该是每轮自适应生成的**。L3 格栅不是状态图——它定义的是「认知的空间」（八卦姿态之间的可能性），而不是「认知的路径」。

### vs OpenAI Agents SDK

OpenAI Agents SDK 强调工具调用和护栏。Agent 可以调用任何工具，但只要不触发护栏即可。

太极补充了：**「护栏」不只是安全规则，更是认知边界**。L4 真理和 L5 自我意识形成了「认知护栏」——不只是阻止危险行为，更引导 Agent 的认知方向。

## 结语：为什么需要「空的架构」？

回到开头的问题：为什么 Agent 架构需要「空」？

因为**现实世界是变化的**。

- 今天的需求和明天不同
- 这个任务和那个任务不同
- 这一轮的上下文和下一轮不同

如果 Agent 的认知结构是固定的，它只能适应固定类型的问题。太极架构通过「空」——每一轮都重新编织认知策略——让 Agent 能够适应**无限变化的任务空间**。

这不仅仅是技术上的创新，更是哲学上的回归。从《易经》的「易」——变化——出发，太极架构试图回答一个古老的问题：

> **一个系统如何在保持稳定的同时，又能持续演化？**

它的答案：让系统的核心是「空」的。不是「什么都没有」的空，而是「什么都可以成为」的空。

> *「虚而待物，无为而无不为。」*
>
> —— 庄子《人间世》
