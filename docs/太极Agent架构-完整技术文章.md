# 太极（Taiji）Agent 架构：用易经智慧重塑 AI 认知循环

> 当 AI Agent 的思考方式不再被固定的 prompt 框住，它会变成什么样？

---

## 一、问题：为什么主流 Agent 框架都「长一个样」？

如果你用过 AutoGPT、CrewAI 或 LangGraph，你会发现它们的核心模式惊人地相似：

1. 你写一个固定的 system prompt
2. 你注册一堆固定的工具函数
3. Agent 在一个固定的循环里反复调用 LLM

**问题出在哪里？**

这套模式的本质是「模板化认知」——无论面对什么任务，Agent 的思维方式都是一样的。它像一条流水线，只会按预设的模具生产。

但人类的思维不是这样的。我们读论文时用分析模式，写代码时用创造模式，决策时用评估模式，执行时用执行模式——**我们根据情境切换认知姿态**。

有没有一种架构，能让 AI Agent 也做到这一点？

有。它叫**太极（Taiji）**。

---

## 二、太极架构的哲学根基：空

太极架构的核心思想来自《易经》的太极、两仪、四象、八卦与六爻。其中最根本的概念是——**「空」**。

> **空 ≠ 无，空 = 未定的可能性。**

在传统框架中，一切都被写死了：

| 领域 | 传统方式 | 太极的「空」 |
|------|---------|------------|
| 系统提示词 | 固定的 system prompt | 每轮动态编织，永远不重复 |
| 工具集 | 写死的工具列表 | 每轮从八卦格栅动态加载 |
| 认知库 | 静态的知识库 | 持续演化，永远有空间接纳新经验 |

这意味着：太极架构**永远不会用同样的方式思考同一个问题两次**。

### 「空」的三层体现

**第一层：空的系统提示词**

Weaver（架构的核心调度引擎）每轮读取 L3 格栅（八卦），根据当前任务的认知姿态动态编织系统提示词。没有固定不变的 system prompt——每一次执行，认知策略都不同。

**第二层：空的工具集**

工具不是写死的，而是 Weaver 每轮从八卦格栅中动态发现和加载的。工具随着认知状态变化而出现或消失。当 Agent 处在「创造模式」（乾卦）时，它看到的是创造类工具；当它切换到「执行模式」（坤卦）时，执行类工具才出现。

**第三层：空的认知库**

L1-L5 不是静态的百科全书，它们随着经验持续演化。每次任务完成，暗驱（Anqu/反思组件）分析日志，提炼新模式，更新认知库。认知库始终处于「将满未满」的状态——永远有空间接纳新的经验。

## 三、编织器（Weaver）：架构的核心调度引擎

如果太极架构是一个人，Weaver 就是那个**织布的人**。

它不做决策，不发号施令，而是像织布机一样，把散落的线（认知格栅、技能工具、执行历史、目标蓝图）织成一张可用的布（系统提示词 + 工具定义 + 执行指导），交给执行层去运行。

### Weaver 每轮做四件事

**1. 织认知策略**

读取 L3 格栅（八卦），确定当前任务的认知姿态（爻）。判断当前应该用创造模式（乾）还是承载模式（坤），是快速启动（震）还是深度渗透（巽），是破局挑战（坎）还是明照评估（离）。

**2. 织工具**

从八卦格栅中探索关联的 L1 技能和 L2 模型，动态绑定到当前轮次的可用工具。这就像一位工匠，根据手头的工作挑选合适的工具——而不是把所有工具都带在身上。

**3. 织执行指导**

把八卦中的工作流步骤注入系统提示词，让执行层知道在这一轮应该用什么节奏、什么哲学来执行。是快刀斩乱麻（震卦「快速启动」），还是润物细无声（巽卦「深度渗透」）？

**4. 织跨轮记忆**

把上一轮的执行结果编织进新一轮的上下文，形成连续的认知流。这保证了 Agent 不会每次「失忆」，而是能积累经验、持续成长。

### Weaver 的代码级理解

Weaver 的核心逻辑大致如下：

```
function weaver_weave(round_context):
    # 1. 从 L3 格栅读取八
    trigram = read_trigram_from_grid(round_context.task_type)
    
    # 2. 确定认知姿态（爻位）
    yao = determine_yao(trigram, round_context.round_number)
    
    # 3. 动态发现工具
    tools = discover_tools(trigram.gua, round_context.goal)
    
    # 4. 编织系统提示词
    system_prompt = compose_system_prompt(trigram, yao, tools)
    
    # 5. 注入跨轮记忆
    memory = load_memory(round_context.goal_id)
    full_context = weave_memory(system_prompt, memory)
    
    return full_context, tools
```

这段逻辑每轮执行一次。因为 Weaver 每一轮都在重新编织，所以系统永远不会被死板的模板锁死——这就是「空」在调度层的体现。

## 四、六爻循环：前台的认知执行过程

太极架构的前台（TPN，Task Positive Network）由六爻组成，形成一个完整的认知循环：

```
Mingjue（明觉/感知） → Weaver（编织器） → Yang（阳/执行动作）
  → Yin（阴/审批） → Executor（执行器） → 暗驱（Anqu/反思）
  → Sixiang（思变/决策）
```

### 各爻详解

**初爻 · 明觉（Mingjue）** — 接收外部信息，感知当前状态和可用资源。相当于人类的「睁眼」瞬间。

**二爻 · 编织器（Weaver）** — 将散落的信息编织成可执行的策略。相当于人类的「构思」阶段。

**三爻 · 阳（Yang）** — 提出执行意图，决定要做什么。相当于人类的「行动意愿」。

**四爻 · 阴（Yin）** — 审批者的角色，用安全规则和伦理标准检查阳提出的意图。这是一个双层审批机制：
- 前层：硬编码规则（如「禁止写入系统目录」）
- 后层：LLM 用 L4 真理和 L5 自我意识做语义审批

**五爻 · 执行器（Executor）** — 实际执行被批准的意图。调用工具、写入文件、执行命令。

**上爻 · 暗驱（Anqu）** — 反思执行结果，记录经验教训，提炼模式。这一步的输出会触发后台 DMN 的认知演化。

**思变（Sixiang）** — 决策下一步走向：继续当前路径、切换策略、还是完成任务。

## 五、八卦认知网格：八种思维模式

太极架构定义了八种认知姿态，对应八卦：

| 卦 | 认知姿态 | 五行 | 生命周期 | 适用场景 |
|----|---------|------|---------|---------|
| ☰ **乾** | 创造/开创 | 金 | 生 | 头脑风暴、创意生成、架构设计 |
| ☷ **坤** | 承载/执行 | 土 | 长 | 按部就班执行、代码实现、测试 |
| ☳ **震** | 启动/激发 | 木 | 育 | 快速原型、启动新项目、Bootstrap |
| ☴ **巽** | 渗透/分析 | 木 | 化 | 代码审查、性能分析、需求分析 |
| ☵ **坎** | 破局/挑战 | 水 | 收 | 解决难题、突破瓶颈、修复 Bug |
| ☲ **离** | 明照/评估 | 火 | 藏 | Code Review、质量检查、回顾总结 |
| ☶ **艮** | 止定/聚焦 | 土 | 安 | 中止发散、聚焦核心、稳定版本 |
| ☱ **兑** | 表达/输出 | 金 | 复 | 撰写文档、输出报告、发布成果 |

这八种姿态之间通过**五行生克关系**相互影响：

- **生（促进）**：木生火（震/巽的深入分析 → 离的明照评估）
- **克（抑制）**：金克木（乾的无限创造会抑制巽的细化分析）
- **相冲**：水火不容（坎的破局 vs 离的求稳）

Weaver 会根据任务的生命周期阶段选择匹配的八卦姿态，并在必要时切换。

## 六、认知库层级（L1-L5）：架构的长期记忆

太极架构有五个层级的认知库，从底层技能到顶层自我意识：

```
L5: SOUL/AGENTS/TOOLS/USER/MEMORY
    ↑ 自我意识、身份认同、长期个人记忆
    
L4: truths/
    ↑ 从经验中提炼的不可动摇的原则（「永远不在生产环境做危险操作」）
    
L3: grids/
    ↑ 八卦思维网格，连接权重动态调整
    
L2: models/
    ↑ 可信赖的工作流模式（「问题分析的 5 步法」「代码重构的标准流程」）
    
L1: skills/
    ↑ 可安装的工具和能力（「curl 命令使用」「Python 单元测试」）
```

### 认知演化过程

```
任务日志 → Anqu 分析 → 提炼模式 → 触发认知演化
  → 更新 L1/L2/L3/L4
  → Weaver 在下轮感知到格栅变化 → 行为调整
```

每一次任务完成，Anqu 分析日志，提取出「这个任务中哪些做法有效」「哪些认知姿态更合适」，然后更新认知库。这意味着太极架构**能从经验中学习**——这是它与所有其他框架最本质的区别。

## 七、DMN：后台的认知演化引擎

除了前台 TPN（六爻循环）之外，太极还有一个后台系统——DMN（Default Mode Network，默认模式网络）。

### TPN vs DMN

| 维度 | TPN（前台） | DMN（后台） |
|------|------------|------------|
| 功能 | 执行当前任务 | 整理经验、更新认知 |
| 节奏 | 每轮活跃 | 任务间隙/空闲时 |
| 产出 | 完成任务 | 更新认知库 |
| 类比 | 工作时的专注思维 | 洗澡时的灵光一闪 |

### DMN 的工作流程

1. Anqu 将执行日志写入分析队列
2. DMN 消费者在后台消费这些日志
3. 提取成功模式 → 更新 L2 models/
4. 提取失败的反模式 → 更新 L4 truths/
5. 调整连接权重 → 更新 L3 grids/
6. Weaver 在下轮感知到格栅变化 → 行为调整

这就是太极架构的自我演化闭环。

## 八、与传统框架的对比

### 对比总表

| 维度 | 太极 (Taiji) | AutoGPT | CrewAI | LangGraph | OpenAI Agents SDK |
|------|-------------|---------|--------|-----------|------------------|
| **核心哲学** | 易经六爻 + 空性 | 自主任务拆解 | 角色协作 | 状态机图 | 函数调用链 |
| **system prompt** | 每轮动态编织 | 固定 prompt | 固定角色 prompt | 固定节点 prompt | 固定 instruction |
| **工具发现** | 动态从八卦格栅加载 | 预注册列表 | 预注册列表 | 预注册列表 | 预注册列表 |
| **自我演化** | ✅ Anqu + DMN | ❌ 无 | ❌ 无 | ❌ 无 | ❌ 无 |
| **认知库** | L1-L5 层级库 | ❌ 无 | ❌ 无 | ❌ 无 | ❌ 无 |
| **安全审批** | 双层审批 | ❌ 无内置 | ❌ 无内置 | ❌ 无内置 | 有限审批 |
| **成本** | 零成本 | 需 API Key | 需 API Key | 需 API Key | 需 API Key |

### 太极的差异化优势

1. **认知灵活性** — 传统框架用固定模板思考，太极每轮重新编织认知策略。这意味着太极可以适应不同类型、不同复杂度、不同领域的任务。
2. **自我演化能力** — 唯一一个能从每次执行中学习并改进自身的 Agent 框架。用得越多，越了解用户的偏好和思维方式。
3. **安全架构** — 双层审批机制（硬编码规则 + LLM 语义审批）是目前最细粒度的安全模型之一。
4. **哲学深度** — 易经六爻 + 空性哲学不仅是装饰，而是实实在在影响架构设计的核心原则。

## 九、实际应用场景

### 场景一：长期代码重构项目

在传统框架中，每次重构 Agent 都需要重新理解代码库。在太极中：
- 第1轮：震卦（启动）→ 快速扫描代码库
- 第2-5轮：坤卦（执行）→ 逐步重构
- 第6轮：离卦（评估）→ 检查重构质量
- DMN：将重构模式存入 L2 models，下次同类型任务更快

### 场景二：多领域知识工作

太极 Agent 可以同时处理代码编写、文档撰写、数据分析等不同领域任务，因为 Weaver 每轮会根据任务类型切换认知姿态。代码任务用巽卦（深度分析），文档任务用兑卦（表达输出），数据分析用乾卦（创造探索）。

### 场景三：自我进化的个人助手

随着使用时间增长，太极 Agent 会：
- 记住你偏好的代码风格（L5 记忆）
- 总结出适合你的工作流（L2 models）
- 形成你的「思维模式」偏好（L3 grids）

用得越久，越了解你。

## 十、快速开始

### 安装

```bash
git clone https://github.com/wenge6090-cell/Taiji.git
cd Taiji
pip install -r requirements.txt
```

### 创建第一个目标

```bash
python main.py --create "分析当前目录下的项目结构并生成报告"
```

### 查看六爻执行过程

```bash
python main.py --goal "分析项目结构" --verbose
```

### 查看认知库演化

```bash
python main.py --inspect --models
python main.py --inspect --grids
```

## 结语：空，然后无限

太极架构不是一个生产级框架——至少目前不是。它是一个**认知架构实验**，将《易经》的古老智慧与现代 AI Agent 设计结合，探索「空性编织」和「自我演化」的可能性。

它的核心不是「又多了一个 Agent 框架」，而是提出了一个根本性问题：

**如果 Agent 的思考方式本身可以像人类一样灵活切换，我们能创造出什么样的 AI 系统？**

答案在「空」中——空不是缺失，是未定的可能性。
