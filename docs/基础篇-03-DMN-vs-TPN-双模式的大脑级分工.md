# 基础篇·03：DMN vs TPN——双模式的大脑级分工

> **核心论点**：主流 Agent 框架把"执行"和"学习"混在一起——同一个 LLM 调用既要完成任务又要提取经验。太极架构将认知分为 DMN（默认模式网络，后台认知演化）和 TPN（任务正向网络，前台任务执行）两个独立循环，两者互不阻塞、互为养分，这才是真正的"学习型Agent"。

---

## 引言：为什么你的 Agent 不会"越做越聪明"？

假设你有两个 Agent：

- **Agent A**：做第 1 个任务时很笨，需要 10 轮才能完成；做第 100 个任务时还是很笨，仍然需要 10 轮
- **Agent B**：做第 1 个任务时笨（10 轮），但做第 50 个任务时只需要 3 轮，做第 100 个任务时几乎 1 轮就能完成

你会选哪个？

答案显而易见。但现实是：**几乎所有主流框架产出的 Agent 都是 Agent A 类型**。

为什么？因为它们混淆了两个根本不同的认知过程：

1. **执行（Execution）**：调用工具、读取文件、写入产出——这是"做事"
2. **学习（Learning）**：分析成败、提取模式、更新策略——这是"变聪明"

在 AutoGPT、LangGraph、CrewAI 等框架中，这两个过程被挤在同一个 LLM 调用中：

```python
# 伪代码：主流框架的"学习"方式
response = llm.generate(f"""
当前任务: {task}
历史记录: {history}
工具结果: {tool_result}

请继续执行任务。同时，从刚才的执行中学习经验。
""")
```

注意看：**"执行"和"学习"是作为同一个 prompt 中的两条指令发给 LLM 的**。

这就像你在写代码时，编辑器每隔 5 秒问你一次："这段代码写得怎么样？要不要重构？"——你根本没法专注。

更严重的问题是：**LLM 在做执行时没有足够的认知预算去深入学习**。它只能浅层地"记住"刚才的教训，但无法将教训提炼为可复用的模式。

太极架构的解法是：**把执行和学习拆成两个独立的循环**——TPN 负责执行，DMN 负责学习，两者异步运行、互不阻塞。

## 第一章：大脑中的 DMN 与 TPN

### 1.1 神经科学的发现

2010 年代，神经科学家发现人脑中存在两个显著拮抗的网络：

**TPN（Task-Positive Network，任务正向网络）**：
- 当你专注于某项任务时激活——写代码、玩围棋、开车
- 激活区域：背外侧前额叶、顶叶等
- 特征：**对外部世界的专注操作**

**DMN（Default Mode Network，默认模式网络）**：
- 当你休息、走神、做白日梦时激活——洗澡时灵光乍现
- 激活区域：内侧前额叶、后扣带回、角回等
- 特征：**对内部世界的反思整合**

关键发现是：**TPN 和 DMN 是拮抗的**——一个激活时，另一个被抑制。你不能同时专注于做任务和反思经验。大脑需要在两种模式之间切换。

这解释了为什么"边执行边学习"是反大脑的：执行时学习深度不够，学习时执行会中断。

### 1.2 太极架构中的对应

太极架构将这一神经科学原理映射到 AI Agent 的架构设计中：

```
┌──────────────────────────────────────────────────────┐
│                   太极架构·双循环                      │
│                                                      │
│  ┌──────────── TPN（前台执行）────────────┐           │
│  │                                         │           │
│  │  明觉 → 织 → 阳 → 阴 → 行动 → 暗驱     │           │
│  │  (感知)  (策略) (意图) (审批) (执行) (日志)│          │
│  └──────────────┬──────────────────────────┘           │
│                 │ 执行日志                              │
│                 ▼                                      │
│  ┌──────────── DMN（后台认知）────────────┐            │
│  │                                         │           │
│  │  暗驱 → 思变 → L1-L5 认知库更新         │           │
│  │  (分析)  (决策)  (模式提取/存储)         │           │
│  └──────────────┬──────────────────────────┘           │
│                 │ 提炼后的模式                          │
│                 ▼                                      │
│           下一轮 TPN 的织（Weaver）                     │
│           加载最新认知资产到系统提示词                  │
└──────────────────────────────────────────────────────┘
```

**TPN（Task-Positive Network）** = 六爻循环的"行动半环"：明觉→织→阳→阴→行动
- 职责：完成当前轮次的具体任务目标
- 产出：写入文件、调用 API、执行搜索
- 特性：**专注、高效、不被打断**

**DMN（Default Mode Network）** = 六爻循环的"反思半环"：暗驱→思变→认知库更新
- 职责：分析执行日志、提取经验模式、更新认知资产
- 产出：L1 技能优化、L2 模型更新、L3 格栅调整
- 特性：**深度、整合、跨轮学习**

这两者的关系不是"先执行再学习"的串行关系，而是**两个同时运行、异步交互的循环**。

## 第二章：双循环如何互不阻塞

### 2.1 关键设计：暗驱是 TPN 的终点，也是 DMN 的起点

在六爻循环中，暗驱（Anqu）是承上启下的关键节点：

```
TPN 轮次执行：
明觉 → 织 → 阳 → 阴 → 行动
                            │
                            ▼
                        暗驱（收集执行日志）
                            │
                ┌───────────┴───────────┐
                ▼                       ▼
          思变（本轮回车）      DMN 异步处理（跨轮学习）
                │                       │
                ▼                       ▼
         下一轮明觉               L1-L5 认知库更新
```

暗驱在 TPN 侧做两件事：
1. **本轮回车**：记录本轮的执行结果，供思变做"继续/重试/完成"决策
2. **异步投递**：将执行日志投递给 DMN 处理管道，DMN 异步分析

**关键机制**：暗驱的投递不阻塞 TPN。TPN 可以立即进入下一轮，而 DMN 在后台慢慢分析。

实际上，TPN 不需要等待 DMN 完成分析。DMN 的产出（经验模式、技能优化）会在下一轮 TPN 的"织"环节被加载——如果 DMN 还没分析完，织就加载之前的认知资产；如果分析完了，织就加载最新的。

```python
# 伪代码：双循环的异步交互
class TaijiLoop:
    def run_tpn_round(self, round_num):
        # TPN 执行（不等待 DMN）
        perception = mingjue.perceive(round_num)     # 明觉
        strategy = weaver.weave(perception)           # 织（加载最新 DMN 资产）
        intent = yang.propose(strategy)               # 阳
        approved_intent = yin.approve(intent)         # 阴
        result = executor.execute(approved_intent)    # 行动
        logs = anqu.collect_logs(result)              # 暗驱
        
        # 异步投递给 DMN（不阻塞）
        anqu.async_dispatch_to_dmn(logs)
        
        return logs
    
    def run_dmn_background(self):
        # DMN 后台异步运行
        while True:
            log_batch = anqu.receive_from_tpn()       # 接收 TPN 日志
            if log_batch:
                patterns = anqu.analyze(log_batch)     # 提取模式
                sibian.decide(patterns)                # 思变决策
                cognition_lib.update(patterns)         # 更新 L1-L5
```

### 2.2 TPN 如何反哺 DMN

TPN 的执行结果通过三种方式反哺 DMN：

**方式一：执行日志 → 模式提取**
每一次 TPN 的执行（搜索、写入、调用 API）都会产生日志。DMN 的暗驱组件会分析这些日志，提取出"什么策略有效"、"什么工具适合什么场景"等模式。

```python
# TPN 执行日志样本
{
    "round": 7,
    "action": "web_search",
    "query": "工业零部件跨境贸易政策",
    "result": "success",
    "tokens_used": 2341,
    "strategy": "宽泛搜索",
    "evaluation": "结果太泛，缺乏深度"
}
```

DMN 分析后产出：
```python
# DMN 提取的模式
{
    "pattern": "search_strategy_refinement",
    "observation": "宽泛搜索在早期探索有用，但第3轮后需要聚焦搜索",
    "actionable": "当轮次 >= 3 时，织应注入'聚焦搜索'策略",
    "confidence": 0.85
}
```

**方式二：失败经验 → 技能库优化**
当 TPN 在某个工具调用上反复失败时，DMN 可以更新 L1 技能库，调整该工具的使用方式或替代方案。

**方式三：成功经验 → 模型库强化**
当 TPN 发现一个高效的执行模式时，DMN 可以将这个模式存入 L2 模型库，供后续轮次参考。

### 2.3 DMN 如何反哺 TPN

DMN 的认知产出通过"织（Weaver）"反哺 TPN：

```
DMN 认知库
    │
    ├─ L1 技能定义更新 ───────────┐
    ├─ L2 经验模型更新 ───────────┤
    ├─ L3 八卦格栅调整 ───────────┤
    └─ L4/L5 高层次认知 ──────────┤
                                   ▼
                           织（Weaver）
                                   │
                           编织到下一轮系统提示词
                                   │
                                   ▼
                           TPN 执行（带着更聪明的认知）
```

具体来说：

- **L1 更新**：织会检查 L1 技能库是否有新增或更新的工具定义，如果有，将其注入系统提示词的工具定义部分
- **L2 更新**：织会加载 L2 模型库中与当前情境匹配的经验模式，作为"建议策略"注入提示词
- **L3 更新**：织会根据 L3 格栅的最新八卦状态，选择当前轮次的认知姿态
- **暗驱反馈**：织会读取上一轮暗驱的输出，将"教训"和"建议"显式写入提示词

```python
# 伪代码：织加载 DMN 资产
class Weaver:
    def weave(self, perception):
        # 加载 DMN 最新资产
        l1_skills = cognition_lib.get_l1_skills()
        l2_models = cognition_lib.get_l2_models(
            context=perception.context
        )
        l3_grid = cognition_lib.get_l3_grid(
            current_gua=perception.recommended_gua
        )
        anqu_feedback = cognition_lib.get_latest_anqu_feedback()
        
        # 编织系统提示词
        system_prompt = f"""
        【当前认知姿态】：{l3_grid.gua_name}
        【建议策略】：{l2_models.strategy}
        【可用工具】：{l1_skills.tool_definitions}
        【上一轮教训】：{anqu_feedback.lesson}
        【建议改进】：{anqu_feedback.suggestion}
        """
        
        return system_prompt
```

### 2.4 关键对比：双循环 vs 主流框架

| 维度 | 主流框架（单线程） | 太极架构（双循环） |
|------|------------------|------------------|
| 执行与学习的关系 | 混在一起，同一次 LLM 调用 | 拆分为 TPN 和 DMN 两个独立循环 |
| 学习时机 | "执行过程中顺便学习" | "执行后异步深度分析" |
| 学习深度 | 浅层记忆（上下文拼接） | 深层模式提取（存入 L1-L5 认知库） |
| 跨任务学习 | 无（新任务从零开始） | 有（L1-L5 持续积累） |
| 认知预算 | 执行和学习争抢同一预算 | 各自有独立预算 |
| 阻塞关系 | 学习阻塞执行，执行阻塞学习 | 互不阻塞，异步交互 |
| 可扩展性 | 上下文窗口有限，历史越长越差 | 认知库结构化存储，不依赖上下文长度 |

## 第三章：DMN 的四种认知演化模式

DMN 不是简单的"分析日志"，它包含四种不同深度的认知演化模式：

### 3.1 模式一：模式提取（Pattern Extraction）

最基础的 DMN 功能。暗驱分析单轮或多轮的执行日志，提取出可复用的执行模式。

```
输入：10 轮搜索日志
输出模式：
- "当搜索工业数据时，使用英文关键词 + site:.gov 效果最好"
- "当搜索中文政策时，使用百度百科 + 政府网站效果最好"
- "第5轮之后，宽泛搜索的 ROI 急剧下降"
```

**存储位置**：L2 模型库（经验模式）

### 3.2 模式二：策略调整（Strategy Adjustment）

基于提取的模式，DMN 调整 L3 格栅的八卦配置。

```
输入：发现"宽泛搜索"在后期效果差
输出调整：
- 修改震卦（启动期）的执行参数：搜索深度从 0.3 提升到 0.7
- 修改巽卦（分析期）的关联规则：增加"深度优先"约束
```

**存储位置**：L3 八卦格栅

### 3.3 模式三：技能发现（Skill Discovery）

DMN 发现现有 L1 技能库的不足，自动补充新工具或新技能定义。

```
输入：3 次调用 read_file 失败，原因是文件路径格式错误
输出技能更新：
- 新增 L1 技能：path_normalizer（路径规范化）
- 修改现有 read_file 技能：增加路径格式验证步骤
```

**存储位置**：L1 技能库

### 3.4 模式四：元认知演化（Meta-Cognition Evolution）

最高层次的 DMN 演化。DMN 反思自身的反思模式——"我过去的模式提取方式是否有效？"

```
输入：过去 20 轮的模式提取质量评估
输出元认知更新：
- "我发现提取的模式中 30% 是伪模式（过拟合到特定情境）"
- "我需要在模式提取时增加交叉验证步骤"
- "高风险模式需要至少 3 次复现才能入库"
```

**存储位置**：L4 真理库 / L5 自我意识层

## 第四章：实战案例——双循环如何在跨境信息差任务中工作

让我们用一个具体的实战案例来展示双循环的实际运作。

**场景**：太极 Agent 执行"跨境工业信息差"目标——搜索中国工业零部件在海外的市场机会。

### 第 1-3 轮：TPN 探索期

```
TPN 第1轮：
  → 明觉：感知目标——需要搜索工业零部件市场
  → 织：注入震卦（启动）姿态，建议广泛搜索
  → 阳：提出"搜索工业零部件市场报告"
  → 阴：批准
  → 行动：web_search("industrial components market overview")
  → 结果：获取了泛泛的市场报告
  → 暗驱：记录日志，投递给 DMN

DMN 异步分析：
  → 分析第1轮日志
  → 提取模式："宽泛搜索只返回泛泛内容，需要更聚焦"
  → 更新 L2 模型库

TPN 第2轮（DMN 资产已更新）：
  → 明觉：感知到 DMN 的更新
  → 织：加载 DMN 建议——"聚焦搜索"，注入巽卦姿态
  → 阳：提出"搜索 specific 品类：轴承 vs 齿轮"
  → ...（执行聚焦搜索）
```

### 第 4-7 轮：DMN 深度演化

```
第4轮后，DMN 积累了足够数据：
  → 模式提取："中文关键词搜索海外市场不如英文关键词"
  → 策略调整：修改搜索工具的默认语言参数
  → 技能发现：新增"翻译+搜索"组合技能

第5轮 TPN 执行时：
  → 织加载了 DMN 的新技能和策略
  → Agent 自动使用英文关键词搜索
  → 结果质量明显提升
```

### 第 8-12 轮：跨领域迁移

```
DMN 进一步演化：
  → 元认知反思："搜索策略的优化模式也适用于其他信息差场景"
  → 更新 L3 格栅：将"聚焦搜索"策略从品类领域扩展到区域领域
  → 更新 L4 真理库："信息差搜索的核心是找到未被合并的信息源"
```

这就是双循环的威力：**TPN 在执行中积累数据，DMN 在后台将数据转化为智慧，智慧再反哺下一轮的执行**。

## 第五章：为什么单线程模式做不到

有人可能会问："我在 prompt 里加一句'同时请从刚才的执行中学习经验'，不就行了吗？"

答案是：**不行，原因有三。**

### 5.1 认知预算限制

LLM 的单次调用有其"认知预算"——attention 的分配、上下文窗口的大小。

假设一次 LLM 调用有 100% 的认知预算：
- 如果任务复杂，90% 预算用于执行，10% 用于学习
- 如果任务简单，70% 预算用于执行，30% 用于学习

不管怎么分配，**执行和学习是在争抢同一份预算**。

而在双循环中：
- TPN 调用：100% 预算用于执行
- DMN 调用：100% 预算用于学习

这意味着 DMN 的学习深度是单线程模式的 3-10 倍。

### 5.2 上下文污染

单线程模式下，"学习"的结果表现为修改上下文。比如：

```
第1轮上下文："搜索失败，因为关键词太宽泛"
第2轮上下文："搜索失败，因为关键词太宽泛。使用了更具体的关键词，效果提升"
第3轮上下文："搜索失败，因为关键词太宽泛。使用了更具体的关键词，效果提升。尝试了轴承品类..."
```

上下文越来越长，关键信息被稀释。到了第 20 轮，LLM 要在一堆历史信息中找到当前任务的关键信息。

而在双循环中：
- TPN 的上下文只包含当前轮次的信息——**每轮从空开始**
- DMN 的认知库是结构化存储——模式、策略、技能各自独立存放
- 织只加载与当前轮次最相关的 DMN 资产

### 5.3 缺乏深层模式提取

单线程模式下，"学习"本质上是 LLM 在 prompt 上下文中"记住"过去的经验。这是一种**表象记忆**，不是**深层模式提取**。

深层模式提取需要：
1. 跨多轮的数据聚合
2. 统计分析（哪些策略成功率更高）
3. 因果推断（为什么这个策略有效）
4. 抽象泛化（这个模式是否适用于其他场景）

这些操作在单次 LLM 调用中几乎不可能完成，但在 DMN 的异步深度分析中是可以做到的。

| 特性 | 单线程 Agent | 太极双循环 Agent |
|------|------------|----------------|
| 执行效率 | 每次调用都在"边执行边学习"（内耗） | 执行和执行之间不干扰（专注） |
| 学习深度 | 浅层上下文记忆（只有"记住"） | 深层模式提取（"理解"+"泛化"） |
| 跨任务学习 | 无 | 有（认知库持续积累） |
| 认知预算 | 执行和学习共享 100% | 执行和学习各占 100% |
| 上下文管理 | 线性增长（历史越长越慢） | 每轮清空（认知资产结构化存储） |
| 可扩展性 | 受限于 LLM 上下文窗口 | 不受限（认知库独立扩展） |

当你看到 Agent 做 100 个任务后仍然像第 1 个任务一样"笨"时，原因只有一个：**它的架构不支持学习**。它不是不愿意学，而是它的架构把执行和学习混在了一起，导致两个都做不好。

太极的 TPN + DMN 双循环，就是为此而设计的。
