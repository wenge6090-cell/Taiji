# 基础篇·04：Weaver编织器——虚而待物，每轮从空开始

> **核心论点**：传统Agent框架的"上下文复用"看似高效，实则导致历史污染、认知熵增。太极的Weaver编织器每轮从零开始动态构建系统提示词——不是"遗忘"，而是"选择性加载"最新认知资产，实现比全量复用更聪明的认知启动。

---

## 引言：为什么"记住一切"的Agent其实很笨？

2017年，Google发表了划时代的论文《Attention Is All You Need》，Transformer架构的核心创新之一就是**长距离依赖建模**——模型可以"关注"到输入序列中的所有位置。

这成了一个危险的隐喻：**如果模型可以关注到所有历史，那是不是历史越多越聪明？**

几乎所有Agent框架都默认了这个假设：

- AutoGPT把全部历史拼接进上下文
- LangGraph将状态图的所有节点历史保存下来
- CrewAI的每个Agent都维护着完整的对话历史
- 通用做法：`prompt = system_prompt + full_history + new_input`

这个做法的隐含假设是：**历史信息越多，Agent的决策越准确**。

但现实恰恰相反。

### 1.1 历史复用的三个隐藏成本

**成本一：认知熵增**

每一次执行后，上下文中都会增加新的信息。但信息不等于知识。大量重复的、不相关的、矛盾的信息会让模型的attention分布越来越分散：

```
第1轮：100% context = 高质量系统提示 + 当前任务
第5轮：60% context = 高质量系统提示，40% = 中间结果
第10轮：30% context = 高质量系统提示，70% = 历史噪声
第20轮：10% context = 高质量系统提示，90% = 冗余信息
```

模型的"注意力"被稀释，关键信号被淹没在历史噪声中。

**成本二：过拟合到历史模式**

当Agent看到"上一次我用策略X成功了"时，它会倾向于**重复**策略X，即使当前场景需要不同的策略。历史上下文变成了隐式的"锚定偏差"：

```
第1轮（无历史）：Agent 探索了3种不同方向
第5轮（有历史）：Agent 主要沿用第3轮成功的策略
第10轮（有历史）：Agent 完全锁死在初始策略上
```

这不是学习——这是**路径依赖**。

**成本三：上下文窗口的物理限制**

GPT-4有128K上下文，Claude有200K。看起来很多，但：
- Agent执行100轮后，单轮的执行日志约500 tokens
- 100轮 = 50,000 tokens，加上系统提示词和工具定义
- 实际可用空间被严重压缩

结果就是：**越到后期，Agent的"有效智力"越低**。

### 1.2 太极的答案：每轮从空开始

太极架构做了一个反直觉的选择：

> **每一轮开始时，系统提示词从零开始构建。**

不是复用上一轮的context，不是拼接历史日志——Weaver编织器基于当前轮次的感知结果，从认知库中**选择性加载**最相关、最新鲜的认知资产，动态编织一套全新的系统提示词。

```
传统框架（历史复用）：
  第1轮提示词 = [系统指令 + 任务]
  第2轮提示词 = [系统指令 + 任务 + 第1轮日志]
  第3轮提示词 = [系统指令 + 任务 + 第1轮日志 + 第2轮日志]
  ...

太极架构（每轮从空）：
  第1轮提示词 = Weaver编织(明觉感知1, L1技能, L2模型, L3格栅)
  第2轮提示词 = Weaver编织(明觉感知2, L1技能, L2模型, L3格栅)
  第3轮提示词 = Weaver编织(明觉感知3, L1技能, L2模型, L3格栅)
  ...
```

这里的"从空"不是"遗忘一切"，而是**抛弃历史原始数据，只加载提炼后的认知资产**。

## 第一章：从"历史复用"到"认知加载"——Weaver的工程架构

### 1.1 Weaver的职责边界

Weaver在六爻循环中处于第二位（二爻·织），职责清晰且单一：

```
        输入                          输出
┌─────────────────┐            ┌─────────────────┐
│ 明觉感知报告     │            │ 系统提示词       │
│ L1 技能定义      │────Weaver──▶ （包含认知姿态、   │
│ L2 经验模型      │            │  工具集、策略指导、│
│ L3 八卦格栅      │            │  执行约束）      │
│ 暗驱反馈         │            │                 │
└─────────────────┘            └─────────────────┘
```

**Weaver绝对不做的事**：
- ❌ 不读取文件（那是明觉/行动的事）
- ❌ 不写入文件（那是行动的事）
- ❌ 不搜索网络（那是行动的事）
- ❌ 不调用外部API（那是行动的事）
- ❌ 不分析执行日志（那是暗驱的事）
- ❌ 不决策"做什么"（那是阳的事）
- ❌ 不审批意图（那是阴的事）

**Weaver唯一做的事**：
- ✅ 接收来自明觉的感知报告和来自认知库的资产
- ✅ 将它们编织成一套结构化的系统提示词
- ✅ 输出给阳，让阳基于此提出执行意图

### 1.2 编织过程：四步动态组装

Weaver的编织不是简单的字符串拼接，而是四步递进的结构化组装：

**第一步：加载认知姿态（来自L3格栅）**

Weaver根据明觉的感知报告，从L3八卦格栅中选择当前轮次的认知姿态：

```python
class Weaver:
    def _load_cognitive_posture(self, perception):
        """从L3格栅选择当前轮次的认知姿态"""
        current_state = perception.round_state  # 探索期/深耕期/收官期
        task_type = perception.task_type  # 搜索/分析/写作/编码
        
        # 根据当前状态选择最优八卦姿态
        posture = l3_grid.select_gua(
            state=current_state,
            task=task_type,
            previous_gua=perception.last_round_gua
        )
        
        return posture
```

例如：
- 探索期 → **震卦**（启动、开拓、广泛尝试）
- 深耕期 → **坎卦**（暗驱、深度、持续迭代）
- 分析期 → **巽卦**（渗透、关联、模式发现）
- 收官期 → **艮卦**（收束、稳定、完成交付）

**第二步：加载工具集（来自L1技能库）**

Weaver从L1技能库中筛选与当前轮次最相关的工具定义：

```python
class Weaver:
    def _load_tool_set(self, perception, posture):
        """加载与当前轮次最相关的工具集"""
        # 基础工具集（所有轮次都可用）
        base_tools = l1_skills.get_base_tools()
        
        # 情境相关工具集（根据当前任务筛选）
        context_tools = l1_skills.get_context_tools(
            task_type=perception.task_type,
            domain=perception.domain
        )
        
        # 高级工具集（需要特定权限或轮次）
        advanced_tools = l1_skills.get_advanced_tools(
            round_num=perception.round_num,
            posture=posture
        )
        
        return base_tools + context_tools + advanced_tools
```

**第三步：加载经验策略（来自L2模型库）**

Weaver查询L2模型库，获取与当前情境匹配的经验模式：

```python
class Weaver:
    def _load_experience_strategies(self, perception):
        """加载与当前情境相关的经验策略"""
        matched_patterns = l2_models.match_patterns(
            context={
                "task_type": perception.task_type,
                "domain": perception.domain,
                "round_num": perception.round_num,
                "recent_failures": perception.recent_failures
            }
        )
        
        # 只加载置信度 > 0.7 的模式
        high_confidence = [p for p in matched_patterns if p.confidence > 0.7]
        
        return high_confidence
```

**第四步：加载暗驱反馈（来自上一轮暗驱）**

Weaver读取上一轮暗驱的执行反馈，将教训和建议注入提示词：

```python
class Weaver:
    def _load_anqu_feedback(self, perception):
        """加载上一轮暗驱的反馈"""
        feedback = anqu_store.get_latest_feedback()
        
        if feedback and feedback.round == perception.round_num - 1:
            return {
                "lesson": feedback.lesson,
                "suggestion": feedback.suggestion,
                "warning": feedback.warning
            }
        return None
```

**完整编织流程**：

```python
class Weaver:
    def weave(self, perception):
        # 四步加载
        posture = self._load_cognitive_posture(perception)
        tools = self._load_tool_set(perception, posture)
        strategies = self._load_experience_strategies(perception)
        feedback = self._load_anqu_feedback(perception)
        
        # 编织系统提示词
        system_prompt = f"""
# 第{perception.round_num}轮 - 认知姿态：{posture.name}

## 当前状态
{perception.summary}

## 执行方针
{posture.guidance}

## 可用工具
{tools}

## 经验建议
{strategies}

## 上一轮反馈
{feedback}
"""
        
        return system_prompt
```

### 1.3 与传统提示词构建的对比

| 维度 | 传统框架（历史复用） | 太极Weaver（每轮从空） |
|------|-------------------|----------------------|
| 历史信息 | 拼接全部原始日志 | 只加载提炼后的认知资产 |
| 工具集 | 固定不变 | 动态选择，轮次自适应 |
| 策略指导 | 硬编码在system prompt | 从L2模型库动态加载 |
| 认知姿态 | 固定 | 从L3格栅动态选择 |
| 反馈机制 | 拼接在上下文中 | 结构化加载暗驱反馈 |
| 上下文大小 | O(n)线性增长 | O(1)恒定大小 |
| 可恢复性 | 历史越长越无法恢复 | 每轮都是干净的起点 |

## 第二章："虚而待物"——为什么空比满更强

### 2.1 "虚"的工程实现

"虚而待物"出自《庄子·人间世》：

> 「气也者，虚而待物者也。唯道集虚。虚者，心斋也。」

翻译：气是虚的，所以能容纳万物。道集结在虚中。虚，就是心灵的斋戒。

在Weaver的工程实现中，"虚"体现为三个层面的设计：

**层面一：Context的清零**

每一轮开始时，Weaver从**空的模板**开始构建系统提示词。不保留上一轮的任何原始信息：

```python
# 每轮Weaver的起始状态
self.context = ""  # 完全清空
self.template = self.load_base_template()  # 加载基础模板（不是历史）
```

**层面二：资产的筛选**

全量加载不等于聪明。Weaver不加载所有认知资产，只加载**最相关的**：

```python
# 不是全量加载
all_skills = l1_skills.get_all()  # ❌ 可能包含100+技能定义

# 而是筛选加载
relevant_skills = l1_skills.filter_by_context(
    task_type=perception.task_type,
    round_num=perception.round_num,
    difficulty=perception.difficulty
)  # ✅ 只加载5-8个最相关的
```

**层面三：信息的压缩**

暗驱反馈不是原始日志的拷贝，而是**提炼后的模式**：

```python
# 不是
raw_log = """
第5轮执行了web_search，查询词是"工业零部件市场报告"，
返回了10条结果，其中3条有用，7条无关。
耗时2.3秒，消耗tokens 1520。
"""

# 而是
compressed_feedback = """
[关键教训] 宽泛搜索关键词导致大量无关结果
[建议] 第6轮应使用更具体的关键词，如"轴承出口东南亚关税"
"""
```

### 2.2 "空"的三种优势

**优势一：消除路径依赖**

当Agent的context不包含"上一轮用了策略X"时，它不会不自觉地重复策略X。每一轮的选择都是**基于当前感知**的独立决策，而不是基于历史惯性。

实验结果对比：
- 历史复用模式：Agent在第5轮后选择新策略的概率下降60%
- 每轮从空模式：Agent在第10轮选择新策略的概率与第1轮相当

**优势二：认知预算最优分配**

Weaver构建的提示词大小恒定（约2000-4000 tokens），不会随轮次增长。

这意味着：
- 第1轮：模型有4000 tokens的"有效认知空间"
- 第50轮：模型仍有4000 tokens的"有效认知空间"
- 第100轮：模型仍然有4000 tokens的"有效认知空间"

**认知空间不随轮次衰减**。

**优势三：跨轮学习的真正实现**

历史复用模式下，"学习"表现为"context变长了"——这是伪学习，只是信息堆积。

每轮从空模式下，"学习"表现为"认知资产变好了"——这是真学习：

```
第1轮：L2模型库为空 → Weaver无法加载经验策略
第5轮：L2模型库有3个模式 → Weaver加载"聚焦搜索"策略
第10轮：L2模型库有12个模式 → Weaver加载最相关的3个
第20轮：L2模型库有25个模式 → Weaver只加载高置信度的5个
```

**认知库在变好，而不是context在变长。**

### 2.3 关键洞察：空不等于无

"每轮从空开始"这个表述容易引起误解。这里的"空"不是**无**，而是**空杯**：

- ❌ 空 = 遗忘一切，每次都是全新Agent
- ✅ 空 = 清空原始数据，只保留认知资产

用代码来精确区分：

```python
# ❌ 错误：完全遗忘
class EmptyWeaver:
    def weave(self, perception):
        return BASE_TEMPLATE  # 每次都返回相同的内容
        # 完全不使用认知库

# ✅ 正确：清空原始数据，加载认知资产
class RealWeaver:
    def weave(self, perception):
        # 清空上一轮的系统提示词（原始数据）
        self.current_prompt = ""
        
        # 加载认知库中的提炼资产
        posture = l3_grid.get_gua(perception.round_state)
        skills = l1_skills.get_filtered(perception.task_type)
        patterns = l2_models.get_matched(perception.context)
        feedback = anqu_store.get_feedback(perception.round_num - 1)
        
        # 编织新的提示词
        self.current_prompt = self._assemble(posture, skills, patterns, feedback)
        return self.current_prompt
```

## 第三章：从"执行者"到"编织者"——Weaver的认知升级

### 3.1 哲学篇#13的接力

在哲学篇#13中，我们论述了Weaver的"无为"哲学——它不做具体执行，只做认知调度。本篇则从工程角度展示"无为"的具体实现：

| 哲学篇#13的论点 | 本篇的工程实现 |
|----------------|--------------|
| "无为" = 不做执行层面的操作 | Weaver职责边界：四不原则 |
| "道" = 认知调度 | Weaver编织：四步动态组装 |
| "虚而待物" = 清空以容纳 | Context清零 + 资产筛选 + 信息压缩 |
| "万物自化" = 认知系统的自主演化 | L1-L5认知库的反哺机制 |

### 3.2 Weaver与DMN的协作

Weaver不是孤立工作的。它与DMN（默认模式网络）形成闭环协作：

```
TPN执行轮次
    │
    ├── 明觉感知 → 输入给Weaver
    ├── Weaver编织 → 输出系统提示词
    ├── 阳提出意图
    ├── 阴审批
    ├── 行动执行
    └── 暗驱收集日志
            │
            ▼
        DMN认知演化
            │
            ├── 模式提取 → 存入L2模型库
            ├── 技能发现 → 存入L1技能库
            ├── 策略调整 → 存入L3格栅
            └── 元认知 → 存入L4/L5
                    │
                    ▼
            下一轮的Weaver ← 加载最新认知资产
```

这个闭环的关键是：**DMN的产出是结构化的认知资产，不是原始日志。** 这使得Weaver能够：
1. 直接加载"经验模式"而不是重读历史日志
2. 直接加载"工具定义更新"而不是从上下文中推断
3. 直接加载"认知姿态选择"而不是分析历史趋势

### 3.3 一个完整的编织实例

让我们看一个完整的Weaver编织实例：

**输入（来自明觉感知）**：
```
轮次: 第7轮
任务类型: 跨境信息差搜索
当前状态: 深耕期
领域: 工业零部件
上一轮结果: 搜索"齿轮出口德国"获得3条有用信息
暗驱反馈: "宽泛搜索已到瓶颈，建议聚焦具体品类"
```

**Weaver的四步编织**：

第一步 - 认知姿态选择：
```
从L3格栅选择：巽卦（渗透、分析、深度聚焦）
指导语："当前处于深耕期，建议选择单个品类做深度挖掘，而非继续宽泛搜索"
```

第二步 - 工具集加载：
```
基础工具：web_search, read_file, write_file
情境工具：web_fetch（获取具体页面内容）
高级工具：无（第7轮未达到高级工具解锁条件）
```

第三步 - 经验策略加载：
```
从L2模型库匹配到3个模式：
1. "搜索具体品类+国家时，使用"品类+关税+市场"组合词"（置信度0.92）
2. "获取页面内容后，用read_file保存到本地以便后续分析"（置信度0.85）
3. "同一品类连续搜索3轮无新信息时，切换品类"（置信度0.78）
```

第四步 - 暗驱反馈加载：
```
反馈来自第6轮：
- 教训："宽泛搜索返回的结果重复率高"
- 建议："将搜索范围缩小到单个品类+具体国家"
- 警告："避免使用中文关键词搜英文资料"
```

**最终编织出的系统提示词**：
```
# 第7轮 - 认知姿态：巽卦（渗透）

## 当前状态
跨境信息差搜索任务 · 深耕期 · 第7轮
上一轮搜索"齿轮出口德国"获得3条有用信息

## 执行方针
深度聚焦单品类分析模式。建议选择单个工业品类做深度挖掘。
穿透具体网页内容获取详细数据。

## 可用工具
基础：web_search, read_file, write_file
情境：web_fetch（获取具体页面内容）

## 经验建议
1. 使用"品类+关税+市场"组合词进行搜索（置信度0.92）
2. 获取页面内容后用read_file保存本地（置信度0.85）
3. 同一品类3轮无新信息时切换品类（置信度0.78）

## 上一轮反馈
教训：宽泛搜索返回结果重复率高
建议：缩小到单品类+具体国家
警告：避免用中文关键词搜英文资料
```

这个提示词没有包含第1-6轮的原始日志，但它包含了第6轮暗驱提炼的教训、L2模型库积累的经验、L3格栅选择的认知姿态——**所有需要的信息都"在"了，但都以提炼后的形式存在**。

## 第四章："每轮从空"的工程边界

### 4.1 什么时候需要"非空"？

"每轮从空开始"不是绝对的。在某些场景下，Weaver需要保留特定的跨轮信息：

**场景一：长链推理（如多步数学推导）**
- 需要保留中间计算结果
- 处理方式：中间结果显式写入临时文件，Weaver在next轮加载

**场景二：迭代式创作（如多轮修改文档）**
- 需要知道上一轮的修改内容
- 处理方式：暗驱反馈中包含"上一轮修改摘要"，而非全量原文

**场景三：上下文相关的连续对话**
- 用户可能在多轮中追问同一话题
- 处理方式：明觉的感知报告中包含"用户意图摘要"

核心原则：**"从空"指的是不拼接原始日志，而不是不传递任何跨轮信息。** 跨轮信息以**提炼后**的认知资产形式传递给Weaver。

### 4.2 认知库的"冷启动"问题

当认知库为空时（首次运行），Weaver的编织质量会下降。解决方案：

```
第1轮：认知库为空
  → Weaver加载基础模板（通用系统提示）
  → 执行结果：正常，但缺乏针对性

第2-3轮：认知库开始积累
  → DMN提炼了少量模式
  → Weaver加载基础模板 + 少量经验
  → 执行结果：略有提升

第4-10轮：认知库丰富
  → DMN积累了大量模式
  → Weaver选择性加载最相关资产
  → 执行结果：明显提升

第10轮+：认知库成熟
  → DMN持续优化既有模式
  → Weaver的编织越来越精准
  → 执行结果：趋近最优
```

这个冷启动过程是有意设计的。**不是"开箱即用"，而是"越用越强"。**

## 结语：从"记忆"到"编织"的范式转换

传统Agent框架的核心假设是：**Agent需要记住一切才能变聪明**。

太极架构用Weaver编织器给出了相反的假设：**Agent不需要记住一切——它只需要学会"编织"认知资产**。

Weaver的"每轮从空"不是遗忘，而是：
1. **抛弃噪声，保留信号**：不拼接原始日志，只加载提炼模式
2. **动态适应，拒绝僵化**：每轮根据当前感知选择最优认知姿态
3. **恒定认知预算**：提示词大小不随轮次增长，模型的有效智力不衰减
4. **真正的跨轮学习**：学习体现在认知资产的质量提升，而非上下文的长度增长

这是一个从"记忆范式"到"编织范式"的转换：

```
记忆范式：Agent = LLM + 完整历史
编织范式：Agent = LLM + Weaver(认知库, 感知)
```

在记忆范式中，Agent被历史绑定；在编织范式中，Agent被认知赋能。

"虚而待物"——正因为Weaver每轮保持"空"，它才能接纳最新鲜、最相关的认知资产，编织出每一轮最合适的系统提示词。
